## 확인된 문제와 수정 권고

### 1. 높음: 1부 체크포인트와 4~9부 모델의 구성이 다름

[1부](../../notebooks/vlm-from-scratch/notebooks/part-01-minimal-vlm.py#L172)는 `google/vit-large-patch16-224` + `HuggingFaceTB/SmolLM-360M`을 사용한다. 저장된 프로젝터의 첫 가중치는 `[960, 1024]`다. 반면 [4부:357](../../notebooks/vlm-from-scratch/notebooks/part-04-multi-task.py#L357) 이후는 ViT-Base + SmolLM-135M을 구성해 `[576, 768]`을 기대한다.

같은 실행 ID로 1→12부를 진행했을 때 4, 5, 6, 7, 8, 9부에서 `RuntimeError: Error(s) in loading state_dict for VisionProjector`가 발생했다. GPU 메모리 부족이 아니라 CPU의 상태 복원 단계에서 실패했다.

원본을 바꾸지 않고 별도 `a40-isolated` 실행 ID에서 큰 캡션 체크포인트를 제외하자 4부는 기반 모델부터 학습·저장을 완료했고, 6~8부는 호환되는 4부 결과로 진행했다. 5부도 캡션 체크포인트가 없는 시작 경로로 완료했다. 이는 연속 실행 오류를 수정한 것이 아니라 **실패 원인을 분리한 검증**이다.

권장 수정은 체크포인트 `config`의 모델 이름·차원으로 구성 요소를 재생성하는 것이다. 혹은 파트 전체의 기반 모델 설정을 통일하고 체크포인트 경로를 모델 구성별로 나누어야 한다. 단순히 `strict=False`로 가리는 것으로는 크기 불일치가 해결되지 않는다.

증거: `remote-results/summary.json`, 각 파트의 `*-result.json`, `remote-results/isolated/summary.json`.

### 2. 높음: 9부가 JSON 객체가 아닌 유효한 JSON에서 중단

[JSON 파싱:1045](../../notebooks/vlm-from-scratch/notebooks/part-09-image-editing.py#L1045)은 `json.loads()`의 결과를 그대로 반환한다. [편집 적용:1059](../../notebooks/vlm-from-scratch/notebooks/part-09-image-editing.py#L1059)는 반환값이 딕셔너리라고 가정하고 `.get()`을 호출한다.

실제 COCO 이미지와 SmolLM-135M으로 1에포크·2배치 학습한 뒤 생성 결과가 JSON 숫자로 파싱되어 `AttributeError: 'float' object has no attribute 'get'`가 발생했다. 생성 길이는 테스트에서 8토큰으로 제한했으므로 기본 50토큰 실행에서도 항상 발생한다고 단정하지 않는다. 그러나 숫자·배열·null도 유효한 JSON이므로 현재 예외 처리만으로는 응답 스키마를 보장하지 못한다.

권장 수정: 최상위 결과가 dict인지, `operation`이 지원하는 문자열인지, `params`가 dict인지 검사하고 실패 시 안전한 기본 연산으로 처리한다.

증거: `remote-results/isolated/part-09-image-editing-result.json`과 해당 로그. 모델 학습은 완료됐고, 학습 후 편집 시연에서 중단됐다.

### 3. 높음: 12부 TrOCR 입력에 RGB 변환이 없음

[ocr_image_trocr:200](../../notebooks/vlm-from-scratch/notebooks/part-12-ocr-latex.py#L200)은 이미지를 RGB로 변환하지 않고 processor에 전달한다. 실제 IAM 이미지에서 `ValueError: Unsupported number of image dimensions: 2`가 발생했다.

동일한 설치 환경과 TrOCR processor로 별도 점검한 결과, PIL `L` 이미지는 같은 오류가 발생하고 `RGB` 이미지는 `[1, 3, 384, 384]`로 전처리에 성공했다. 권장 수정: processor 호출 전에 PIL 이미지를 RGB로 변환한다.

증거: `remote-results/retry12/part-12-ocr-latex-result.json`, `remote-results/ocr-input-modes.json`.

### 4. 높음: 12부 수식 OCR의 잘못된 SmolLM 임베딩 접근

[학습 경로:323](../../notebooks/vlm-from-scratch/notebooks/part-12-ocr-latex.py#L323)와 [추론 경로:536](../../notebooks/vlm-from-scratch/notebooks/part-12-ocr-latex.py#L536)이 `language_model.embeddings.word_embeddings()`를 사용한다. 실제 SmolLM-135M을 `AutoModel`로 읽으면 LlamaModel이므로 해당 속성이 없다.

독립 GPU 구성 요소 검사에서 실제 ViT-Base·SmolLM 가중치로 순전파와 `predict_latex()`를 각각 호출했고 둘 다 `AttributeError: 'LlamaModel' object has no attribute 'embeddings'`가 재현됐다. 앱 전체 경로는 그보다 앞선 TrOCR 입력 문제에서 멈추므로 이 오류는 별도 호출로 검증했다.

권장 수정: 두 곳을 `language_model.get_input_embeddings()(input_ids)`로 교체한다.

증거: `remote-results/gpu-components.json`의 12부 두 항목.

### 5. 중간: 10부가 양자화 packed 가중치를 크기에서 누락

[SimpleVLM:231](../../notebooks/vlm-from-scratch/notebooks/part-10-compression.py#L231)과 [TinyVLM:710](../../notebooks/vlm-from-scratch/notebooks/part-10-compression.py#L710)의 크기 계산은 parameters/buffers만 합산한다. 실제 동적 양자화 Linear 285개의 packed 가중치가 누락된다.

- FP32 모델: **952.373 MiB**.
- 양자화 모델이 출력한 크기: **111.114 MiB**.
- 누락된 packed 가중치만: **210.234 MiB**.
- 이를 더한 최소 텐서 크기: **321.348 MiB**.
- 표시된 압축률: **8.57배**. 누락 가중치를 포함하면 압축률은 **최대 2.96배**다.

마지막 값은 전체 직렬화 파일이나 상주 메모리 크기가 아니라, 적어도 빠진 가중치를 더한 하한 용량을 기준으로 한 상한 압축률이다. 권장 수정: FP32·INT8 양쪽의 저장된 state_dict 파일 크기를 같은 방식으로 비교하거나 packed 데이터도 합산한다. 실제 INT8 순전파는 성공했다.

증거: `remote-results/quantized-size.json`, `remote-results/part-10-compression.log`.

## 테스트 사본의 변경 조건과 검증 한계

원본 `.py`의 SHA-256은 전송 전후 모두 동일했다(`manifest.json`, `remote-results/source-sha256.json`). `.env`는 전송하지 않았고 Runpod API 키는 로컬 CLI 인증에만 사용했다.

다음 변경은 `remote-results/*-bounded.py`, `isolated/*-bounded.py`, `retry12/*-bounded.py`에 남긴 실행 사본과 테스트 도구에만 적용했다.

- 지시된 실행 버튼을 `app.run(defs={"mo": marimo, "run_notebook": SimpleNamespace(value=True)})`로 활성화.
- 명시된 에포크 수 최대 1, DataLoader 배치 크기 최대 2, 배치 반복 최대 2.
- 생성 토큰 최대 8, 확산 추론 단계 2, 반복 개선/재시도 1, 변형 후보 2.
- 원격 데이터는 스트리밍으로 최대 16행을 읽고 참조를 반복해 64행의 작은 뷰를 구성. `.select()` 범위와 테스트 인덱스를 작은 뷰에 맞춤.
- 3부의 3600 경계는 48로 바꿔 학습·테스트 목록을 구성. 별도 실행에서는 5·6부의 2000·450 같은 고정 인덱스를 작은 뷰 안으로 매핑.
- 일부 평가 루프는 작은 데이터 뷰 때문에 원문의 큰 오프셋 조건에서 건너뛰었다. 4부의 큰 오프셋 VQA 평가도 이에 해당하며, 세 작업의 시연 함수 호출과 구분한다.
- matplotlib 화면 표시 대신 그림을 PNG로 저장하고 메모리에서 닫음.
- 각 앱에 150초 제한을 두었으며 실제 타임아웃은 발생하지 않음.

따라서 반복된 데이터는 독립 검증 세트가 아니며, 평가 정확도·F1·생성 결과를 수렴이나 일반화 성능으로 해석할 수 없다. 8토큰 JSON 생성은 정상 학습 설정보다 짧으므로 JSON 형식 성공률 평가에도 사용하지 않는다. 언어 모델까지 업데이트하는 원본 학습 루프는 앱 사본에서 실행했고, 독립 구성 요소 검사는 프로젝터 업데이트만 검사했다.

12부의 최초 `Bad split: test[:10]`는 테스트 도구가 원래 비스트리밍 호출을 스트리밍으로 강제한 탓이다. 이를 노트북 결함으로 계산하지 않았다. 재검사 도구에서는 base split `test`에서 샘플링하도록 보완했고, 그 뒤 실제 흑백 이미지 전처리 오류를 확인했다.

## 실행 명령과 재현 자료

원격 작업 루트는 `/workspace/vlm-review`이고 실제 인터프리터는 `notebooks/vlm-from-scratch/.venv/bin/python`이었다.

```bash
# 환경 설치 위치: /workspace/vlm-review/notebooks/vlm-from-scratch
UV_CACHE_DIR=/workspace/cache/uv uv sync --locked

```

실제 실행에는 상위 프로세스 timeout도 적용했다. 테스트 자식 프로세스는 예외를 JSON에 기록하고 반환하므로, 자식 exit 코드가 0이어도 `status=failed`이면 실패로 판정했다. 같은 이름의 스크립트, 수정된 사본, 부분별 로그, JSON 상태와 PNG가 `outputs/vlm-from-scratch/20261111-140926-runpod-a40/remote-results/`에 함께 있다. 이 스크립트의 원격 절대 루트는 재실행 환경에 맞게 바꾸어야 한다. 실행 사본은 원본의 대체 소스가 아니다.
