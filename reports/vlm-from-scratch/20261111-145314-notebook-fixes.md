[A40 실행 보고서](20261111-140926-runpod-a40.md)에서 재현된 다섯 오류를 수정했다. 수정 후 로컬 프로젝트 가상 환경에서 회귀 검사 10개와 12개 앱의 정적 검사·의존성 그래프·실행 전 HTML 출력이 통과했다. 수정 후 GPU 학습·추론은 다시 실행하지 않았으며 새 Runpod 리소스를 생성하지 않았다.

- 실행 ID: `20261111-145314-notebook-fixes` (Asia/Seoul).
- 대상: `notebooks/vlm-from-scratch/`의 노트북 10개, README, 새 회귀 테스트.
- 산출물: [outputs/vlm-from-scratch/20261111-145314-notebook-fixes/](../../outputs/vlm-from-scratch/20261111-145314-notebook-fixes/).
- 수정 전 소스는 산출물 `before/`, 노트북 변경 내역은 `changes.patch`에 보관했다. 기존 A40 보고서는 당시 결과로 유지한다.

## 수정 내용

### 체크포인트 구성과 가중치 복원(2~9부)

체크포인트를 모델 생성 전에 CPU로 읽고, 저장된 `config`의 `vision_model_name`과 `lm_model_name`으로 인코더·언어 모델을 만든다. 실제 은닉 차원으로 프로젝터를 생성하고 config와 차원을 비교한 뒤 두 state_dict를 엄격하게 복원한다. 복원 실패를 초기 가중치로 덮고 진행하던 2·3부 처리도 제거했다.

저장된 tokenizer/image_processor 디렉토리가 있으면 함께 사용하고, 저장된 추가 토큰이 있으면 LM 임베딩 크기를 맞춘다. 체크포인트가 없으면 각 파트의 기존 기본 모델을 유지한다. 6~9부의 멀티태스크 → 캡션 체크포인트 우선순위도 유지한다. 복원 후 CPU 체크포인트의 참조를 해제한다.

이로써 1부의 ViT-Large/SmolLM-360M 체크포인트를 4~9부가 고정된 ViT-Base/SmolLM-135M으로 읽으려던 오류를 해결했다. 실제 선택한 모델에 따라 VRAM 요구량이 달라질 수 있음을 README에 추가했다.

### 편집 응답 검증(9부)

JSON 문법 파싱 후 결과가 dict인지, operation이 지원하는 문자열인지, params가 dict인지 확인한다. 숫자·배열·null·boolean·문자열·알 수 없는 연산·잘못된 params·비문자열 응답이면 기존 그레이스케일 대체 동작으로 반환한다. 올바른 연산과 매개변수는 유지한다. 유효한 JSON 숫자가 `.get()`에서 AttributeError를 일으키던 경로를 제거했다.

### OCR 입력 및 임베딩(12부)

TrOCR 입력을 PIL 이미지로 만든 뒤 RGB로 통일한다. 흑백·RGBA·RGB·numpy 흑백 입력을 검사했다. 수식 OCR의 순전파와 `predict_latex()`는 `get_input_embeddings()`를 사용한다. 비전·언어 차원도 로딩한 모델 config에서 읽도록 변경했다.

### 양자화 용량 계산(10부)

SimpleVLM과 TinyVLM의 `get_model_size_mb()`를 `torch.save(state_dict, BytesIO)`의 직렬화 크기로 변경했다. FP32·INT8에 같은 저장 방식을 적용하므로 packed 가중치도 포함된다. 측정 단위를 MiB로 명시하고 GPU 메모리 사용량과 구분했다. 4배 축소는 양자화 대상 가중치에 관한 이론적 비율이며 전체 모델의 실측 비율과 다를 수 있음을 본문에도 설명했다.

## 검증 환경과 명령

- 작업 디렉토리: `notebooks/vlm-from-scratch/`.
- 인터프리터: 이 프로젝트의 `.venv/bin/python`.
- Linux, Python 3.12.15, torch 2.12.1+cu130, transformers 4.57.6, marimo 0.25.2, torchvision 0.27.1, Pillow 13.0.0.
- CUDA 사용 가능 상태: `False`. CPU에서 검사했다.
- 모든 회귀 검사·HTML 출력에서 `HF_HUB_OFFLINE=1`, `HF_DATASETS_OFFLINE=1` 사용. 외부 모델·데이터를 다운로드하지 않았다.

```bash
# 작업 디렉토리: notebooks/vlm-from-scratch/
VLM_TEST_OUTPUT_DIR=../../outputs/vlm-from-scratch/20261111-145314-notebook-fixes \
HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1 \
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/marimo check --strict notebooks/part-*.py
```

자동 검증 도구는 `vlm_verify_fixes.py`, `vlm_validate_fixed_apps.py`로 산출물에 보관했다. 앞 도구는 수정 전후 소스를 같은 회귀 테스트에 적용하며, 뒤 도구는 각 앱을 import해 그래프와 실행 순서 토큰을 검사한 뒤 버튼을 누르지 않은 HTML을 생성한다.

수정 전 소스에 같은 검사를 적용한 음성 대조는 예상대로 종료 코드 1이었다. 수정 후는 종료 코드 0이다. 수정 전 로그의 실패·예외 수는 하위 사례를 포함하므로 독립 검사 메서드 수와 다르다. `before-regressions.log`, `after-regressions.log`, `verification.json`에 근거를 남겼다.

모델 로더만 임시 구성으로 대체하고, 노트북 안의 원본 클래스·모델 구성 셀·함수 본문을 AST로 추출해 실행했다. 체크포인트는 작은 무작위 ViT/Llama 텐서와 WordLevel 토크나이저로 만들었으며 복원된 모든 가중치를 정확하게 비교했다. 이미지 입력 처리에는 실제 ViTImageProcessor를 사용했고, TrOCR 디코더는 입력 채널을 확인하는 대역을 사용했다. 수식 OCR은 실제 작은 LlamaModel로 순전파·역전파·토큰 생성을 수행했다. 양자화는 실제 PyTorch 동적 INT8 연산을 사용하고 디스크의 저장 파일 크기와 비교했다. 데이터·모델의 외부 리비전은 해당하지 않으며 난수 시드는 7이다.

## 한계와 유지한 동작

이번 검사는 로컬 CPU 회귀 검사와 실행 전 화면 검사다. 수정 후의 실제 가중치 GPU 학습·추론, A40 메모리 사용량, 전체 데이터셋 학습과 생성 품질은 재검증하지 않았다. 이전 A40 통과 결과를 수정 후 GPU 통과 결과로 바꾸어 보고하지 않는다.

8부의 RefCOCO 데이터 소스가 사용 불가할 때 COCO로 전환하는 기존 동작은 유지했다. 실제 RefCOCO 데이터 경로의 검증을 의미하지 않는다. 한글 글꼴은 기존 자동 선택과 README의 운영체제 글꼴 설치 안내를 유지한다. 설치된 PyTorch의 동적 양자화 API 폐기 예정 경고는 회귀 검사에서도 발생했으나 실제 INT8 처리는 통과했다.
