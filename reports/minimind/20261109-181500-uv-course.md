## 단계별 실습 흐름 검토

- 1장 토큰/벡터 → 2장 입력/labels → 3장 Attention → 4장 블록/전체 모델 → 5장 학습 루프로 개념의 선행 관계를 구성했다.
- 5장의 `pretrain.pt`를 6장 분류와 7장 SFT가 각각 읽는다. 분류는 별도 head를 학습하는 분기다.
- 7장의 `sft.pt`에서 8장 LoRA와 9장 DPO가 독립적으로 출발한다. adapter 결과는 DPO에 섞이지 않는다.
- 모든 장을 새 커널로 실행했으므로 이전 장 변수에 숨겨진 의존성이 없다. 연결은 설정·토크나이저 해시를 검증하는 디스크 체크포인트를 사용한다.
- train/valid는 원문·질문을 먼저 분리한다. 단, 매우 작은 비슷한 패턴의 데이터라 강한 일반화 평가가 아니다.
- 10장은 9장 이후의 선택 개념 확장으로 실제 rollout이나 보상 모델 학습을 실행하지 않는다.

외부 모델 가중치를 받지 않고 MiniMind를 무작위 초기화했다. 예제 JSONL은 공통 helper의 고정 문장으로 생성했다. 소스·토크나이저 파일·lock·실제 JSONL의 SHA-256은 [input-manifest.json](../../outputs/minimind/20261109-181500-uv-course/validation/input-manifest.json)에 기록했다. 노트북 파일 해시는 static-audit에 있다.
