## 현재 결과

업데이트된 `.env` 인증으로 Runpod 조회가 성공했다. Secure Cloud RTX 5090 32GB의 가격은 GPU 목록에서 $1.19/hour로 확인됐다. EU-RO-1과 EUR-NO-1 모두 stockStatus=Low를 반환했으나 실제 Pod 생성은 각각 HTTP 400 bad_request로 실패했다.

반환 메시지: `There are no longer any instances available with the requested specifications. Please refresh and try again.`

Pod는 생성되지 않았으며 학습·샘플 생성·모델 업로드도 실행하지 않았다. 이번 생성한 빈 네트워크 볼륨 mm8gssi44m(EU-RO-1), hy7ulhse0h(EUR-NO-1)은 모두 삭제하고 목록 조회로 삭제를 확인했다. 최종 Pod 목록과 볼륨 목록은 모두 비어 있었다. 리소스가 남아 계속 과금되는 상태는 아니다. 짧게 존재한 볼륨의 실제 청구액은 별도로 조회하지 않았다.

## 준비한 구성

`projects/minimind-o/scripts/runpod_vlm_audio/`:
- prepare.py: 리비전 고정 다운로드. caspar VLM 가중치와 해당 토크나이저 사용.
- train.py: VLM의 Thinker, LM head, vision projector를 보존하고 Omni donor의 Talker/audio projector를 사용. 텐서별 출처와 shape, strict loading, 토큰 ID를 실행 시 검증한다.
- 음성 학습: T2A Talker 1epoch(2e-5), A2A audio projector 1epoch(1e-4), A2A 두 모듈 1epoch(2e-5). VLM 전체·외부 인코더는 고정한다.
- 데이터별 128행 검증 분리, seed42, batch16×accum2, sequence1024, audio stop token loss weight10. augmentation/scheduled sampling 비활성화. A2A 입력에 전사 텍스트를 넣지 않는다.
- evaluate.py/infer.py: 음성 4개 및 이미지 샘플 생성, Mimi 디코딩, 자동 전사, 모델 카드·보고서·해시·소스 패키징. 생성의 newline token ID는 VLM 토크나이저에서 계산한다.

## 사용자 재개 요청 후 추가 배치 시도

RTX 5090 재고와 가격을 다시 조회했다. 공식 v2 OpenAPI를 확인하고 GPU 목록을 CUDA12.8 이상 조건으로 조회했다. CUDA별 용량에서 13.2에 available=true가 표시됐고 두 데이터센터는 LOW로 표시됐다. EU-RO-1은 STANDARD 네트워크 스토리지를 지원했다.

CLI와 별도로 `POST https://api.runpod.io/v2/pods`에 명시적인 gpu.minCudaVersion=12.8과 네트워크 마운트, Secure Cloud 조건을 전달했으나 같은 HTTP400 재고 부족 메시지가 반환됐다. Pod는 생성되지 않았다. 이 시도에서 생성한 50GB 볼륨 zll8oy98d4는 삭제하고 최종 Pod·볼륨 목록이 모두 빈 배열임을 재확인했다.

관련 원본은 같은 outputs 폴더의 gpus-retry.json, pod-request.json, pod-retry-error.json, volume-retry.json, final-pods.json, final-volumes.json에 보관했다. 키는 포함하지 않았다. 학습·평가·업로드는 계속 미실행이다.
