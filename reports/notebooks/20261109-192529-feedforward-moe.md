## 구현과 검증 범위

두 파일은 각각 단독 실행하는 한국어 marimo 노트북이다. 원본 `minimind/model/model_minimind.py`의 `FeedForward`, `MiniMindBlock`, `MOEFeedForward`, `MiniMindForCausalLM`을 직접 사용하며 원본 파일은 수정하지 않았다. 예측·실행·관찰·해설과 수정 과제를 포함한다.

FeedForward는 D=4/M=8의 수동 SwiGLU 계산, SiLU와 sigmoid 그림, 토큰별 독립 처리, Attention 뒤의 RMSNorm·FFN·잔차 연결을 확인한다. 학습 예제는 seed 23으로 만든 80개 입력을 64/16개 학습·검증으로 나누는 숫자 회귀다. 목표는 `[x0*x1, SiLU(x2), x0-x3, x1*x2]`이며 새 FFN(seed 24)을 AdamW lr=0.02, weight decay=0으로 학습한다. 언어 모델 학습으로 해석하지 않는다.

MoE는 D=4/M=8/E=3, 토큰 6개의 특징과 읽을 수 있는 수동 router 가중치로 시작한다. 전체 softmax·top-k·선택 가중치·전문가 가중합·선택 횟수·보조 손실을 원본과 비교한다. 별도 top-1 실험은 보조 손실 계수 0에서 straight-through의 router gradient와 미선택 전문가의 0 gradient를 확인한다. 이후 hidden size 16, 1층, Q head 2개, KV head 1개, E=3인 MoE LM(seed 33)을 두 ID 문장 `[1,3,4,2]`, `[1,5,6,2]`로 80 step 학습한다. optimizer는 AdamW lr=0.01, weight decay=0이다. `outputs.loss + outputs.aux_loss`를 사용하며 보조 손실 계수는 0.01이다.

외부 가중치·데이터 다운로드는 없으며 외부 모델·데이터 리비전도 없다. 실습 및 원본 파일 SHA-256은 `metrics.json`에 기록했다.

## 실행 명령

저장소 루트 `/home/mind4u/dev/llm_playground`에서 각각 별도 프로세스로 실행했다.

```bash

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
MPLCONFIGDIR=/tmp/minimind-marimo-mpl MPLBACKEND=Agg \

  outputs/notebooks/20261109-192529-feedforward-moe/validate.py
```

모두 종료 코드 0이었다. `ffn-script.log`, `moe-script.log`, `validation.log`에 기록했다. `validate.py`는 `app.run(defs=...)`로 UI 설정을 바꾸어 일곱 설정을 실행하고 `metrics.json`과 기본 설정의 PNG 네 장을 저장한다.

`notebooks/`에서 정적 검사와 HTML 실행을 수행했다.

```bash
XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
.venv/bin/marimo check minimind_feedforward.py minimind_moe.py --strict --format json

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
MPLCONFIGDIR=/tmp/minimind-marimo-mpl MPLBACKEND=Agg \
.venv/bin/marimo export html minimind_feedforward.py \
  -o ../outputs/notebooks/20261109-192529-feedforward-moe/minimind_feedforward.html

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
MPLCONFIGDIR=/tmp/minimind-marimo-mpl MPLBACKEND=Agg \
.venv/bin/marimo export html minimind_moe.py \
  -o ../outputs/notebooks/20261109-192529-feedforward-moe/minimind_moe.html
```

검사와 HTML 실행 커널의 내부 소켓을 허용하기 위해 해당 명령은 로컬 소켓 제한 밖에서 실행했다. 정적 검사는 두 파일, 문제 0건이었다. 두 HTML 내보내기 역시 종료 코드 0이었다. SiLU 곡선과 MoE의 주 손실·총 손실·보조 손실 그림을 직접 열어 축과 범례를 확인했다.

## 수치 결과

| FFN 중간 차원 / step | 매개변수 | 학습 MSE 전 → 후 | 검증 MSE 전 → 후 |
| --- | --- | --- | --- |
| 16 / 200 (기본) | 192 | 1.36739 → 0.04027 | 0.79978 → 0.12810 |
| 8 / 100 | 96 | 1.36998 → 0.08200 | 0.75219 → 0.17237 |
| 32 / 300 | 384 | 1.36005 → 0.00929 | 0.81092 → 0.09707 |

학습 횟수도 다른 설정이므로 위 표만으로 중간 차원 단독 효과를 결론 내리지 않는다. 세 설정 모두 gate/up/down projection의 첫 gradient norm이 0보다 크고 모든 내장 assertion을 통과했다.

| MoE k / 정규화 | 가중합 최대 오차 | 수동 보조 손실 | LM 주 손실 전 → 후 |
| --- | --- | --- | --- |
| 1 / 끄기 | 1.86e-8 | 0.010000 | 2.10436 → 0.23737 |
| 1 / 켜기 | 1.86e-8 | 0.010000 | 2.10385 → 0.24603 |
| 2 / 끄기 | 1.86e-8 | 0.020872 | 2.10434 → 0.23739 |
| 2 / 켜기 (기본) | 1.77e-8 | 0.020872 | 2.10419 → 0.23646 |

네 설정 모두 직접 계산과 원본이 일치했다. 토큰별 전문가 할당 합은 N*k, top-1 전문가별 횟수는 `[2,2,2]`, top-2는 `[4,2,6]`이었다. 같은 k에서는 결합 정규화 여부를 바꾸어도 이 고정 router의 보조 손실이 같았다. eval 모드에서 원본 aux_loss가 0이 되는 것도 확인했다.

별도의 정규화 top-1 gradient 실험은 router norm 0.001477, 선택된 expert 0의 norm 0.859486, 미선택 expert 1/2의 norm 0이었다. 미선택 전문가도 gradient 객체가 존재하는 원본 구현의 특징을 확인했다. 이 실험은 고정 seed·입력에 대한 결과다.

작은 LM의 다음 토큰 정확도는 네 설정 모두 5/6이었다. 두 문장의 BOS 다음 정답이 서로 달라 6/6을 요구하지 않는다. 일반화나 전문가 역할 분화를 입증하는 결과는 아니다.

## 한계

기본 CPU 예제와 위 설정만 검증했다. FFN UI의 모든 차원·step 조합, 다른 운영체제, GPU·대규모 MoE 분산 통신, 실제 처리 속도·메모리 절감, 외부 데이터 성능, 실제 수강생 이해도와 브라우저 편집기 조작은 검증하지 않았다. 전체 전문가 보유량과 선택 경로 가중치 수를 구분했으며 선택 수만으로 속도 향상을 주장하지 않는다.
