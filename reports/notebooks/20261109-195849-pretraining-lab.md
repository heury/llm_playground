## 구성

`minimind/trainer/train_pretrain.py`와 `minimind/dataset/lm_dataset.py`를 기준으로, 실제 `PretrainDataset`, `init_model`, `get_lr`, `SkipBatchSampler`, `lm_checkpoint`를 사용한다. 원본 trainer 파일의 main이나 train_epoch 전체는 실행하지 않고 CPU 학습 루프를 축소 작성했다. 원본 파일들은 수정하지 않았다.

노트북에는 다음이 포함된다.

- 원문 JSONL 생성, 학습 8개·검증 4개 조합 분할, 학습 텍스트만으로 만든 단어 단위 Fast tokenizer.
- 실제 Dataset의 본문 절단·BOS/EOS 추가·오른쪽 패딩·labels=-100과 모델 내부 next-token shift 확인.
- 유효 정답별 cross entropy, 직접 평균과 원본 loss 비교, 오른쪽 PAD 입력 변경에 대한 유효 예측 불변성.
- 동일 길이의 큰 배치와 누적 gradient 일치, 마지막 불완전 누적 그룹의 원본 나눗셈 영향.
- epoch별 셔플·microstep 학습률·누적·gradient clipping·optimizer step과 추적 표.
- 유효 토큰 수로 가중 평균한 학습·검증 loss/perplexity·토큰 정확도, 원문 12개의 앞부분 이어 쓰기.
- 원본 checkpoint 함수의 실제 저장·복원과 동일 추가 갱신 비교, 원본 코드 대응 표와 과제·해설.

기본 모델은 hidden size 32, 2층, intermediate size 64, Q head 4개, KV head 2개, dropout 0, Dense다. 초기화 seed는 42, shuffle seed는 42+epoch다. 기본 길이 10, batch size 2, 40 epoch, 누적 수 2이며 AdamW lr=0.005, weight decay=0.01, clip norm=1.0을 사용한다. get_lr는 원본 cosine 수식을 그대로 호출한다. CPU float32로 AMP·GradScaler·DDP·compile·wandb를 사용하지 않는다.

외부 데이터·가중치나 토크나이저 다운로드는 없다. 고양이·강아지·소·오리와 수식어 조합을 코드에서 만들고, 검증 원문과 학습 원문은 겹치지 않는다. 검증 단어는 모두 학습 사전에 존재한다. 소스 파일 SHA-256은 `metrics.json`에 기록했다. 생성 JSONL·토크나이저·datasets 캐시·학습 지표·생성 결과·체크포인트는 각 실행의 자동 생성 폴더에 있으며 정확한 경로는 `metrics.json`의 `runtime_output_dir`, `training_dir`에 기록했다.

## 실행 명령

```bash

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \

  outputs/notebooks/20261109-195849-pretraining-lab/validate.py
```

기본 단독 스크립트와 검증 스크립트 모두 종료 코드 0이었다. `script.log`, `validation.log`, `metrics.json`에 기록했다. 검증 스크립트는 아래 세 설정의 모든 셀을 실행하고, step 수·clipping·누적 나눗셈·EOS/PAD·생성 분할·동일 추가 step의 복원을 추가 검증했다.

`notebooks/`에서 다음 검사와 HTML 실행도 수행했다.

```bash
XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
.venv/bin/marimo check minimind_pretraining.py --strict --format json

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
MPLCONFIGDIR=/tmp/minimind-marimo-mpl MPLBACKEND=Agg \
.venv/bin/marimo export html minimind_pretraining.py \
  -o ../outputs/notebooks/20261109-195849-pretraining-lab/minimind_pretraining.html
```

비동기 검사와 HTML 실행 커널의 내부 소켓을 위해 해당 명령은 로컬 소켓 제한 밖에서 실행했다. 정적 검사는 1개 파일, 문제 0건이며 HTML 내보내기 종료 코드도 0이었다. loss·학습률 곡선을 PNG로 저장해 직접 열고 축·범례를 확인했다. 자동 세션 캐시는 `marimo-session/`으로 이동했다.

HTML 내보내기 종료 시 Python resource_tracker가 semaphore 1개 정리 경고를 출력했다(`export.log`). 셀 실행·내장 검증·HTML 생성은 완료됐지만 종료 시 자원 정리까지 경고 없이 끝났다고 보고하지는 않는다. 일반 스크립트와 세 설정 검증 실행에는 이 경고가 없었다.

## 결과

| 길이 / epoch / 누적 수 | microstep / optimizer step | 학습 loss 전 → 후 | 검증 loss 전 → 후 | 다음 소리 정답: 학습 / 검증 |
| --- | --- | --- | --- | --- |
| 10 / 40 / 2 (기본) | 160 / 80 | 2.87710 → 0.42832 | 2.87464 → 0.82257 | 8/8, 4/4 |
| 6 / 10 / 1 | 40 / 40 | 2.89098 → 1.40210 | 2.92379 → 1.47969 | 2/8, 1/4 |
| 8 / 10 / 3 | 40 / 20 | 2.87710 → 1.71270 | 2.87464 → 1.80643 | 2/8, 1/4 |

기본 설정의 검증 perplexity는 17.7190 → 2.2763이었다. 다음 소리 정답은 원문 앞부분을 넣었을 때 바로 다음의 동물 소리 토큰을 기준으로 계산했으며, 문장 전체 정답률과는 구분한다. 다른 설정들은 여러 요인이 동시에 달라지므로 길이·누적 수의 단독 효과를 이 표로 결론 내리지 않는다.

동일 길이 두 microbatch와 큰 배치의 gradient 최대 오차는 세 설정 모두 약 1.2e-7 이하였다. A=3의 마지막 1개 그룹은 원본처럼 loss를 3으로 나눠 갱신되며, 이 경우 10 epoch에서 해당 작은 그룹 갱신이 10번 발생함을 확인했다. clip 후 norm은 모두 허용 오차 내 1 이하였다.

실제 resume 파일에서 모델·optimizer를 복원하고, 같은 추가 배치·LR로 한 optimizer step을 수행한 가중치 최대 오차는 세 설정 모두 0이었다. 모델 가중치 파일과 resume 파일은 각 `training_dir`에 보관했다.

## 해석과 한계

원본의 `loss/accumulation_steps`를 의도적으로 보존했다. 불완전 그룹과 유효 토큰 수가 다른 microbatch에서는 일반적인 전체 토큰 평균과 같다고 주장하지 않는다. 수정 가능한 원본의 실제 동작을 관찰하고, 더 엄밀한 토큰 가중 평균이 필요한 조건을 설명하는 실습이다.

검증 원문을 optimizer에 넣지 않았지만 매우 작은 같은 규칙의 조합 데이터다. 결과를 한국어 일반화 성능으로 해석하지 않는다. max_length를 바꾸면 학습 본문 자체가 잘리므로 perplexity도 동일한 조건끼리 비교해야 한다. epoch·누적 수가 낮은 설정의 손실 감소를 모든 생성 성공으로 보고하지 않았다.

체크포인트 실험은 dropout=0·고정 추가 배치·누적 경계 저장 조건이다. 실제 trainer의 DataLoader 중간 위치, 난수 상태, 미완료 누적 gradient, DDP·혼합 정밀도 재개까지 검증하지 않았다. 모든 UI 조합, GPU·다른 OS, 외부 토크나이저·대규모 데이터, 브라우저 편집기 조작과 실제 수강생 이해도도 미검증이다.
