## 검증 명령

작업 디렉토리: `/home/mind4u/dev/llm_playground`. 아래에서 `PY=notebooks/.venv/bin/python`.

```bash
$PY notebooks/minimind_grpo.py
$PY outputs/notebooks/20261109-201500-grpo-validation/verify_parity.py
notebooks/.venv/bin/marimo check notebooks/minimind_grpo.py
notebooks/.venv/bin/marimo export html notebooks/minimind_grpo.py \
```

검증 환경에서는 `XDG_CONFIG_HOME=/tmp/grpo-config`, `MPLCONFIGDIR=/tmp/grpo-mpl`, `HF_DATASETS_OFFLINE=1`, `HF_HUB_OFFLINE=1`을 사용했다. Dataset 캐시는 노트북이 실행 산출물 경로로 지정한다.

## 결과

- 전체 셀 실행 성공. 실제 RLAIFDataset의 빈 answer 및 마지막 assistant 제외, advantage의 동일 보상/G=1 처리, EOS 포함·이후 제외, reference 불변·gradient 없음, 업데이트 전 ratio=1 확인.
- 원본 trainer AST에서 손실 구간을 그대로 추출하여 GRPO와 CISPO 모두 **손실 값과 현재 logps gradient 일치** 확인. 마스크 제외 위치 gradient=0, 행별 다른 프롬프트 길이에서 다음 토큰 정렬 검증 통과. `parity.json` 및 재현 스크립트 참조.
- 작은 MiniMind: SFT 120 step, GRPO 60 step, B=2, G=8, beta=0.01, AdamW lr=0.0003, seed 123.
- `2 + 2 =`의 정답 확률: 0.597590 → 0.883020.
- `2 + 3 =`의 정답 확률: 0.597491 → 0.910185.
- 두 질문의 정확한 기대 보상: 0.597541 → 0.896603. 최종 greedy 답은 각각 4와 5.
- marimo check: 종료 코드 0, 진단 없음.
- HTML export: 종료 코드 0, 약 351KB의 HTML 생성. 곡선 PNG를 열어 샘플 보상 변동과 기대 보상 개선 확인.

## 검증 한계와 실패 기록

- 초기 실행은 기본 Hugging Face 캐시 쓰기 제한과 generate의 inference tensor 재사용으로 실패했다. 캐시를 outputs로 옮기고 반환 tensor를 clone하여 해결했다.
- 초안의 대칭 SFT 분포와 큰 RL 학습률에서는 EOS로 붕괴하는 결과를 관찰했다. 최종본은 질문별 정답/오답 3:2의 SFT 출발점과 작은 학습률을 사용한다. 위 통과 결과는 최종 설정에만 해당한다.
- 제한 환경에서 정적 검사는 비동기 처리 대기, HTML export는 로컬 커널 소켓 제한으로 실행되지 않았다. 동일한 로컬 검증을 권한 확장으로 실행하여 통과했다. export 종료 때 semaphore 정리 경고 1건이 있었으며 실행 실패나 셀 오류는 없었다.
- 한 토큰 응답과 두 학습 질문의 행동 변화 실습이다. 외부 reward model은 점수 0.2 stub으로 원본 함수 호출 구조만 확인하고, 실제 학습에는 정답 일치 규칙 보상을 썼다.
- 한국어 일반화, GSM8K, 외부 SFT 가중치, 실제 reward model, 긴 응답 학습, 원본 trainer 전체, AMP/DDP/SGLang은 미실행이다. 다중 토큰 마스크·정렬은 별도 수치 예제에서 검증했다.
- HTML은 내보내기와 데이터·그래프 생성을 확인했으며 브라우저 편집기의 사용자 상호작용은 검사하지 않았다.
