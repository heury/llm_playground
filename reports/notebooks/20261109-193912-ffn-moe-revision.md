## 검토 반영

| 검토 항목 | 수정 |
| --- | --- |
| MoE 과제 3에서 expert 0 고정 assertion 실패 | 실제 선택 인덱스로 토큰별 기대 출력을 만들고 선택 횟수에 따라 미선택 gradient를 검사. 부호 +1/-1 UI와 혼합 입력용 함수 제공 |
| FFN의 필요성과 비선형성 비교 부족 | 동일 회귀 데이터·step·optimizer에서 Linear, TwoLinear, SiLU MLP, 원본 SwiGLU를 비교. TwoLinear의 합성 가중치도 직접 검증 |
| 토큰별 독립 처리와 문맥의 연결 부족 | 같은 입력 변경에 대해 FFN 단독과 Attention 포함 블록의 위치별 출력 변화를 비교 |
| 보조 손실 효과 관찰 부족 | 균등·편중 확률 예제와, 동일 초기 LM의 계수 0/0.01 학습 전후 선택 횟수·평균 확률·계수 없는 균형 항 추가 |
| 고정 router와 LM 재학습 설정 혼동 | 두 UI와 셀 의존성을 분리하고 출력·과제에 적용 범위를 명시 |
| straight-through 난도 상승 | scalar p/p와 p-p.detach()+1의 값·gradient를 먼저 비교 |
| Dense와 MoE의 대체 관계 | 동일 입력의 Dense(전문가 0과 같은 가중치)·MoE shape·보유량·출력과 모든 전문가의 첫 토큰 출력을 비교 |

원본 `minimind/model/model_minimind.py`는 수정하지 않았다. 외부 모델·데이터 다운로드나 체크포인트는 없다. FFN은 기존 seed 23의 숫자 80개를 64/16 학습·검증으로 나누고, 모델 초기화 seed 24, AdamW lr=0.02, weight decay=0을 사용한다. 기본 M=16, 200 step이다. 비교 구조의 up/down은 동일 초기값이며, 전체 매개변수 수는 다르므로 동일 용량 비교라고 설명하지 않는다.

MoE는 기존 고정 router의 D=4/M=8/E=3 예제를 유지했다. top-1 probe는 seed 32로 매번 새 모델을 만든다. LM은 hidden size 16, 1층, E=3, Q head 2개, KV head 1개, seed 33의 초기 모델을 복사해 계수 0/0.01을 각각 80 step 학습한다. optimizer는 AdamW lr=0.01, weight decay=0이다. 입력은 `[1,3,4,2]`, `[1,5,6,2]`로 고정했다. 소스 SHA-256은 `metrics.json`에 기록했다.

모두 종료 코드 0이었다. `validate.py`는 FFN M=8/16/32와 200 step, MoE k=1/2·정규화 켜기/끄기 네 설정을 실행했다. LM은 각 설정에서 계수 두 개를 같은 초기 가중치·데이터로 학습했다. 모든 내장 assertion, 네 FFN 구조의 매개변수 수, main+aux=total, 부호 -1과 혼합 전문가 입력을 검증했다. 로그·지표는 `*-script.log`, `validation.log`, `metrics.json`에 있다.

독립성 대조는 LM 설정을 k=2·정규화 켜기로 고정하고, 앞의 고정 router 설정만 k=2·켜기에서 k=1·끄기로 바꿨다. LM의 계수별 지표와 사용량 스냅샷이 정확히 같았다. `independence.log`, `independence.json`에 기록했다. 브라우저 반응형 UI 조작을 자동화한 검증은 아니며, 셀 인자 분리와 실행 결과의 독립성을 확인했다.

## 핵심 결과

기본 M=16/200 step의 동일 회귀 과제 결과:

| 구조 | 매개변수 | 최종 학습 MSE | 최종 검증 MSE |
| --- | --- | --- | --- |
| Linear | 16 | 0.482389 | 0.387117 |
| TwoLinear | 128 | 0.482389 | 0.387127 |
| SiLU MLP | 128 | 0.006729 | 0.010195 |
| SwiGLU | 192 | 0.040273 | 0.128104 |

이 과제·초기화에서는 SiLU MLP의 오차가 가장 작았다. SwiGLU의 일반적 우월성을 주장하지 않고, 비선형성·곱셈 구조와 모델별 표현·최적화 결과를 비교하는 자료로 사용한다.

배치 0의 토큰 위치 1을 바꿨을 때, 위치 2의 출력 변화는 FFN 단독 0, 전체 블록 0.171765였다. 앞 위치 0은 causal Attention 때문에 유지됐다. scalar p=0.7의 두 계산은 출력이 모두 1이지만 gradient는 각각 0과 1이었다.

top-1 부호 +1에서는 전문가 `[0,0]`, -1에서는 `[1,1]`을 선택하여 모두 검증이 통과했다. 추가 혼합 입력은 `[0,1,2]`를 선택했고 세 전문가 모두 0보다 큰 gradient를 받았다. 사용되지 않은 전문가는 gradient 객체가 존재하되 norm이 0이었다.

기본 LM k=2·정규화 켜기의 결과:

| 보조 손실 계수 | 초기 선택 횟수 | 최종 선택 횟수 | 최종 주 손실 | 계수 없는 균형 항 |
| --- | --- | --- | --- | --- |
| 0 | [6,4,6] | [5,5,6] | 0.236377 | 2.034578 |
| 0.01 | [6,4,6] | [7,4,5] | 0.236457 | 1.736889 |

보조 손실 항은 작아져도 선택 횟수 자체가 더 균등해진 것은 아니다. 이 원본의 손실은 선택 빈도와 평균 확률의 곱이므로 두 값과 주 과제 손실을 함께 관찰해야 한다. 노트북에 균등 사용을 보장하지 않는다는 해설을 유지했다. 균등·편중을 사람이 정한 별도 확률 예제의 계수 0.01 손실은 각각 0.010과 0.027이었다.

## 한계와 산출물

이번 검증은 위 CPU 예제·설정에 한정한다. 모든 UI 조합, 모든 자유 입력, GPU·다른 운영체제, 대규모 속도·메모리, 외부 데이터의 일반화, 실제 수강생 이해도는 검증하지 않았다. LM은 입력 8위치의 routing을 기록하지만 주 손실·정확도는 다음 정답이 있는 6위치로 계산한다. BOS 뒤 정답이 둘이므로 정확도 5/6을 실패로 간주하지 않는다.

README의 상대 링크와 Python 구문·줄 끝 공백을 확인했다. HTML, PNG, 로그, 두 검증 스크립트와 지표는 대응 `outputs/`에 보관하며, marimo 자동 세션 캐시도 같은 실행 폴더로 옮겼다. `outputs/`는 gitignore 대상이므로 핵심 결과를 이 보고서에 직접 남겼다.
