## 1. 우선 수정: MoE 과제의 지시와 assertion이 충돌한다

위치: MoE 235, 237, 247, 331행.

과제는 첫 성분의 부호를 바꿔 선택 전문가가 달라지는지 보라고 한다. 실제로 `[2,0.1,...]`, `[1.5,0.2,...]`의 첫 성분을 음수로 바꾸자 expert 1이 선택되지만, 코드는 계속 `experts[0]` 출력과 비교하여 실패했다. 뒤의 gradient assertion도 expert 0만 선택된다고 가정한다.

수강생은 올바르게 과제를 수행했는데 자신의 수정이 틀린 것으로 받아들일 수 있다. FFN 과제 2는 의도적인 assertion 실패를 명시했지만, 이 MoE 과제에는 그런 안내가 없다.

개선: 실제 router의 선택 인덱스로 출력·gradient를 검증하고 표에 선택 여부를 표시한다. 또는 고정 입력용 검증 셀과 자유 실험 셀을 분리한다. 단순히 assertion을 제거하면 관찰 근거까지 잃으므로 권하지 않는다.

## 2. FFN이 왜 필요한지와 중간 차원의 역할을 비교하기 어렵다

위치: FFN 43, 87, 188, 269행.

학생 관점 질문: “세 선형층과 곱셈의 계산은 따라 했지만, 선형층 하나 대신 왜 이 구조가 필요한가요?”

현재는 원본 출력과 수동 계산이 같은지 확인하고 한 모델의 오차가 감소하는 것을 본다. gate를 제거하는 과제도 일치 검증 실패로 끝나 표현 능력을 비교하지 못한다. 중간 차원 확대와 비선형성의 목적이 아직 추상적이다.

개선: 같은 숫자 회귀에서 단일 Linear와 SwiGLU를 비교하고, gate·활성화를 제거한 변형도 같은 조건으로 학습한다. 두 선형층만 연속 적용하면 하나의 선형 변환으로 합쳐지지만, 비선형·곱셈이 있으면 달라짐을 작은 입력으로 보여 준다. 단순히 표본을 더 잘 맞춘 것을 일반적인 우수성으로 해석하지 않는다.

## 3. 토큰별 독립 처리와 문맥 활용을 연결해야 한다

위치: FFN 123, 160행.

독립 처리 실험은 명확하고 유용하다. 다만 “FFN은 다른 단어를 전혀 모르는데 LLM에서 무엇을 배우나요?”라는 질문이 남는다. FFN에 들어오는 h는 이미 Attention으로 문맥이 반영된 표현이라는 연결을 더 강조할 필요가 있다.

개선: 한 토큰 입력만 바꿨을 때 FFN 단독과 Attention을 포함한 블록의 출력 변화 위치를 나란히 비교한다. “현재 FFN 연산이 위치를 섞지 않는다”와 “그 입력에 문맥 정보가 없다”는 다른 주장임을 해설한다.

## 4. 보조 손실의 필요성을 직접 관찰하는 실험이 부족하다

위치: MoE 159, 173, 277, 333행.

수식과 원본 값의 일치는 확인되지만 “왜 이 손실을 줄여야 하는가”는 설명에 의존한다. 정적인 선택 횟수 그림과 학습 중 보조 손실 곡선은 서로 다른 모델에서 나온다. 학습 전후 router 사용량은 표시되지 않아 계수 0/0.01 과제로 사용 편중의 변화를 확인하기 어렵다.

개선: 같은 입력·초기 모델에서 균등 사용과 편중 사용을 비교하고, 계수 0/0.01 학습의 전문가별 선택 횟수·평균 확률을 함께 기록한다. 보조 손실 감소가 균등 선택이나 주 과제 성능 향상을 보장하지 않는다는 기존 설명을 유지한다.

## 5. 정규화 UI가 바꾸는 실험 범위를 구분해야 한다

위치: MoE 60, 98, 271, 329행.

고정 router의 보조 손실은 같은 k에서 정규화 여부와 무관하다. 실습에서도 k=2의 값은 두 경우 모두 0.020872였다. 그러나 UI는 뒤의 LM도 새로 학습한다. 그 최종 보조 손실은 정규화 끄기 0.018868, 켜기 0.017381로 달라졌다. 설명의 “그대로”는 고정 router에 대한 말인데 화면 전체 결과로 받아들이면 모순처럼 느껴질 수 있다.

개선: “수동 router 관찰용 설정”과 “새로 학습되는 LM 설정”을 명확하게 표시하거나 제어를 분리한다. 각 출력에 모델·학습 여부를 표시하고, 고정 가중치 비교와 재학습 비교가 다른 질문임을 적는다.

## 6. straight-through 설명은 작은 gradient 비교를 먼저 거치면 좋다

위치: MoE 209~250행.

수식은 정확하고 gradient가 존재하는 것도 확인된다. 하지만 shape·행렬 곱 수준의 학생에게 detach, hard top-k, 보조 손실, 미선택 전문가의 그래프 유지가 한꺼번에 나온다. 현재는 한 가지 구현의 gradient norm만 보므로 무엇 때문에 기울기가 생겼는지 실험으로 분리하기 어렵다.

개선: scalar p에 대해 p/p와 p-p.detach()+1의 순전파 값·gradient를 나란히 비교한다. 그다음 동일 MoE 가중치로 top-1 정규화 방식만 바꾸어 비교한다. 입력 gradient 차단과 전문가 가중치 gradient는 심화 내용으로 나눈다. 원본의 특수 처리를 모든 MoE의 필수 규칙으로 일반화하지 않도록 한다.

## 7. Dense와 MoE의 대체 관계를 동일 입력으로 비교하면 좋다

위치: MoE 36, 190, 258행.

각 단계의 계산은 잘 드러나지만 별도 FFN 회귀와 별도 MoE LM을 실행하므로 “하나의 FFN을 여러 전문가로 바꾸면 무엇이 달라지는가”를 같은 입력에서 비교하기 어렵다. MoE의 필요성에 대한 실험 근거가 선택 횟수와 매개변수 표에 머문다.

개선: 같은 `[B,T,D]` 입력을 Dense FFN과 MoE에 넣어 shape, 보유량, 선택 경로와 전문가별 출력을 비교한다. 학습 성능까지 비교하려면 데이터·초기화·학습 횟수와 비교 예산을 명시한다. 현재 작은 Python 구현으로 처리 속도나 대규모 성능 우위를 주장하지 않는 기존 한계는 유지한다.

## 실행에서 확인한 좋은 점

- 수동 SwiGLU·MoE 가중합이 원본과 같고, FFN의 토큰 독립성이 코드로 검증된다.
- 같은 200 step에서 FFN M=8/16/32의 매개변수는 96/192/384로 3DM에 맞았다. 학습·검증 오차가 분리되어 있다.
- MoE는 선택 횟수와 softmax·재정규화 가중치를 구분한다. 정규화 켜기·끄기와 top-k 변경이 실제 동작한다.
- 주 손실과 보조 손실의 별도 합산, 추론 모드 보조 손실 0, 보유량과 선택 경로의 구분을 설명한다.
- 속도 향상·전문가 역할·일반화 성능을 샘플 결과만으로 주장하지 않는다.

## 결론과 한계

기본 계산을 따라가는 데는 충분한 자료가 있으나, FFN의 필요성·MoE 보조 손실의 효과를 이해하려면 비교 실험이 더 필요하다. 가장 먼저 고칠 것은 실제 과제 실행을 막는 expert 0 고정 assertion이다. 이어 고정 모델 비교와 재학습 비교를 분리하고, baseline·편중 실험·scalar gradient 비교를 추가하는 순서를 권한다.

이번 요청은 검토이므로 원본 노트북·README는 수정하지 않았다. 일곱 설정의 전체 셀과 과제 3 재현을 실행했지만, 모든 과제·모든 step·계수 조합·브라우저 조작·실제 수강생 이해도는 검증하지 않았다. FFN 과제 2의 의도적 assertion 실패는 이번에 별도로 실행하지 않았다.
