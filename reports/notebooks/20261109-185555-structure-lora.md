## 구현 범위

원본 `minimind/model/model_minimind.py`, `minimind/model/model_lora.py`를 직접 import한다. 원본 구현은 수정하지 않았다. 한국어 설명, 단어 사전, 패딩과 다음 토큰 정답, RMSNorm·GQA·RoPE·causal Attention 직접 계산, SwiGLU와 잔차 연결, 전체 학습, greedy 생성, KV cache, LoRA 학습·저장·복원·병합과 학생 과제를 포함한다.

데이터는 노트북 안의 네 문장(고양이/강아지/소/오리의 소리)이다. 외부 데이터 리비전이나 체크포인트는 없으며 무작위 초기화(seed 42)부터 학습했다. 어댑터 초기화 seed는 7이다. 소스 세 파일의 SHA-256은 산출물의 `metrics.json`에 기록했다.

모델은 hidden size 32, 2층, Query head 4개, KV head 2개, intermediate size 64, 최대 위치 64, dropout 0, Dense 구조다. 원본 매개변수는 19,072개이며 LoRA rank 4에서는 1,024개만 학습한다. 전체 학습 AdamW 학습률은 0.005, LoRA는 0.01, weight decay는 둘 다 0이다. 생성은 greedy, 최대 5개 새 토큰, top_k=0, top_p=1, temperature=1이다.

## 실행 명령

저장소 루트 `/home/mind4u/dev/llm_playground`에서:

```bash

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
MPLCONFIGDIR=/tmp/minimind-marimo-mpl MPLBACKEND=Agg \

```

`validate.py`는 marimo의 `app.run(defs=...)`로 UI 정의를 덮어써 기본 설정과 두 경계 설정의 전체 셀을 실행하고 `metrics.json`, `validation.log`를 남긴다. 일반 스크립트 실행도 종료 코드 0이었다.

`notebooks/`를 작업 디렉토리로 사용한 명령:

```bash
XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
.venv/bin/marimo check minimind_structure_lora.py --strict --format json

XDG_CONFIG_HOME=/tmp/minimind-marimo-config \
MPLCONFIGDIR=/tmp/minimind-marimo-mpl MPLBACKEND=Agg \
.venv/bin/marimo export html minimind_structure_lora.py \
  -o ../outputs/notebooks/20261109-185555-structure-lora/minimind_structure_lora.html
```

marimo의 비동기 검사와 HTML 실행 커널이 내부 소켓을 필요로 하여 해당 두 명령은 샌드박스의 로컬 소켓 제한 밖에서 실행했다. 사용자 설정과 matplotlib 임시 캐시는 `/tmp`를 사용했다. 자동 생성된 세션 캐시는 실행 후 산출물의 `marimo-session/`으로 이동했다.

| 전체 학습 step / LoRA rank | 전체 학습 손실 전 → 후 | LoRA 새 정답 손실 전 → 후 | LoRA 매개변수 | 모든 내장 assertion |
| --- | --- | --- | --- | --- |
| 100 / 4 (기본) | 2.70091 → 0.23993 | 1.43905 → 0.24277 | 1,024 | 통과 |
| 20 / 2 | 2.70091 → 0.83417 | 0.94514 → 0.80567 | 512 | 통과 |
| 160 / 8 | 2.70091 → 0.23549 | 1.56718 → 0.23669 | 2,048 | 통과 |

기본 설정은 전체 학습 후 원래 소리 4/4, LoRA 후 바뀐 소리 4/4를 정확하게 생성했다. 예를 들어 `고양이 는`은 전체 학습 후 `야옹 한다 . <eos>`, LoRA 후 `멍멍 한다 . <eos>`로 이어졌다. 20 step 설정에서는 전체 학습 후 소의 소리를 틀렸으므로 손실 감소를 모든 문장의 학습 성공으로 해석하지 않는다.

검증한 항목:

- 직접 계산한 Attention과 원본 Attention의 출력 일치, 미래 Attention 확률 0, RoPE 전후 Q 벡터 길이 보존.
- SwiGLU·잔차 연결의 직접 계산과 원본 블록 출력 일치.
- 직접 계산한 다음 토큰 cross entropy와 원본 loss 일치. 길이가 다른 문장에 대해 패딩 정답을 제외한 손실도 일치.
- Embedding과 LM head의 실제 가중치 객체 공유.
- 미래 토큰을 바꿔도 앞 출력 불변. 세 설정 모두 KV cache와 전체 계산의 마지막 logits 최대 오차 0.
- LoRA 적용 직후 원본 출력 일치. 학습 후 원본 매개변수 불변, 어댑터 매개변수 변경, 유한 손실과 손실 감소.
- 실제 파일 저장·복원·병합. 기본 설정 복원 최대 오차 0.00112, 병합 최대 오차 0.00556. rank 8의 병합 최대 오차 0.01056. 원본 함수의 float16 저장을 고려한 허용 오차(atol=0.03, rtol=0.01) 내였다.
- `marimo check --strict`: 1개 파일, 문제 0개 (`check.json`). HTML export 종료 코드 0, 약 354 KiB 결과 생성. 공백 검사도 통과.

## 수정 중 발견 및 처리

- 원본 `generate`의 기본 top_k=50은 작은 어휘 수를 넘으므로 실습 호출에 top_k=0을 명시했다.
- `apply_lora`가 클로저로 원래 층을 참조하므로, 적용 모델을 deepcopy하지 않고 매번 원본 복사 → 동결 → LoRA 적용 순서를 사용한다.
- 초기 전체 학습률 0.02에서는 일부 동물 구분이 학습되지 않았다. `tune.py`/`tune.log`에 학습률 비교를 보관하고, 네 문장을 학습한 0.005로 기본값을 조정했다.
