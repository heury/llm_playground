## 검토 관점과 발견 사항

| 관점 | 발견 사항 |
| --- | --- |
| 모델 구조 설명 | 구조·FFN·MoE는 원본 클래스와 수동 계산을 대조하는 방식으로 정확하다(MoE의 `p - p.detach() + 1`, aux 식은 `model_minimind.py`와 일치). 구조 노트북이 다음 단계를 LoRA로 안내해 학습 파이프라인 흐름과 어긋났다. |
| fine tuning 설명 | 사전 학습·SFT·LoRA·증류·DPO·PPO·GRPO 모두 원본 Dataset·손실 함수를 직접 호출한다. 사전 학습에서 학습률 그래프만 있고 `get_lr` 식이 없었다. |
| 단계 구성 | README에 서로 다른 권장 순서가 5개 있었고, 표에 Omni·VLM 미세 조정이 빠져 있었다. 증류·DPO는 선수 과정에서 SFT를 빠뜨렸고, Omni는 VLM 이전에 읽도록 안내했다. **reasoning 단계가 없었다.** MiniMind의 추론은 `reasoning_content` → `<think>` template(SFT)과 think 형식·GSM8K 보상(GRPO)으로 구현되어 있지만, SFT는 이를 의도적으로 제외했고 GRPO는 한 문단만 언급했다. |
| 중복 | LoRA 1~2절이 구조 노트북 1·5절과 같았다(데이터·config·학습 루프·생성 함수·매개변수 표). SFT는 사전 학습의 정답 이동·누적 평균 설명을, 증류는 SFT의 마스크·패딩 설명을 반복했다. GRPO의 clip 표는 PPO 6절과 같았다. VLM 미세 조정 4·5·7절은 VLM 4·6·7절과 같았다. Projector 설명이 VLM·V-SFT·Omni에 세 번 나왔다. marimo 사용 안내(`@app.cell`, `_` 변수)가 거의 모든 노트북 도입부에 반복되었다. |
| 불필요한 코드·문장 | GRPO 첫 셀이 사용하지 않는 `sys`, `datetime`, `Path`를 반환했다. LoRA 데이터 셀이 출력하지 않는 `mo`를 인자로 받았다. VLM과 VLM 미세 조정의 실행 ID 접미사가 모두 `-vlm`이어서 산출물 폴더를 구분할 수 없었다(기준 실행에서 확인). README에 개발용 메모(VS Code 확장의 셀 분류, 삭제된 옛 파일명)가 있었고, 실행 명령에서 일부 노트북이 빠져 있었다. FFN 3절에 "따라서"로 시작하는 문장이 연달아 나와 논리가 어색했다. |
| 이해에 누락된 부분 | 실제 MiniMind template(`<\|im_start\|>`, `<think>`)이 SFT 계열 노트북에 한 번도 나오지 않았다. |

## 수정 내용

**단계 구성**
- README를 4부 학습 경로(구조 → 학습 → 정렬·추론 → 멀티모달)와 단계별 연결점, 13개 노트북 표, 전체 실행·내보내기 반복문, 노트북별 산출물 표로 다시 썼다.
- 모든 노트북의 선수 과정·"다음 실습" 안내를 이 경로에 맞췄다(구조, MoE, 사전 학습, SFT, LoRA, 증류, DPO, PPO, GRPO, VLM, VLM 미세 조정, Omni).

**reasoning 단계 추가**
- `minimind_sft.py` 5-1절: 실제 tokenizer와 `SFTDataset`으로 `reasoning_content`가 `<think>` 블록에 들어가고, think·최종 답·종료 토큰이 하나의 정답 구간이 되는 것을 확인한다. 빈 think의 80% 제거(`post_processing_chat`)도 비교한다. assertion으로 검증하며 학습 모델과 어휘가 다르므로 관찰만 한다.
- `minimind_grpo.py` 3-1절: `thinking_ratio`에 따른 프롬프트 끝(`<think>\n` / 빈 블록), 원본 `calculate_rewards`(AST 추출, 보상 모델은 0.2 stub)와 `score_gsm8k_response`로 6개 응답을 채점한다. 제목·도입·과제 7번도 추가했다.

| 응답 | calculate_rewards | GSM8K |
| --- | --- | --- |
| 올바른 추론 + 정답 | 1.617 | 1.0 correct |
| 너무 짧은 추론 + 정답 | −0.883 | 1.0 correct |
| 형식은 같고 숫자만 오답 | 1.617 | 0.0 wrong_number |
| `</think>` 두 번 | 1.307 | 0.0 format_error |
| 추론 없이 답만 | −0.883 | 1.0 correct |
| `####` 없음 | 1.950 | 0.0 format_error |

판정 근거: 형식 보상은 숫자의 정오와 무관하고(1·3행 동일), GSM8K 보상은 think 길이와 무관하다(1·2행 동일). 이를 노트북 assertion으로 고정했다.

**중복 축소**(단독 실행에 필요한 코드와 검증 assertion은 유지)
- LoRA 1~2절: 설명과 매개변수 표를 제거하고 "구조 노트북과 동일"로 요약했다. 원본 `train_lora.py`가 `SFTDataset`을 쓴다는 점과의 관계도 명시했다.
- SFT 4·7절, 증류 3·4절, VLM 미세 조정 4·5·7절, Omni 2절: 반복 설명을 해당 노트북·절 참조로 바꿨다.
- GRPO: clip 표 셀 2개를 제거하고, PPO 6~7절을 참조하면서 "차이는 advantage의 출처"라는 설명을 추가했다.
- 구조 노트북을 제외한 도입부의 marimo 사용 안내를 제거했다(README "수강생 실습 방법"에 한 번 둔다).

**기타**
- 사전 학습 6절에 `get_lr` 식과 바닥값(0.1·lr₀)을 추가했다.
- VLM 미세 조정의 실행 ID 접미사를 `-vlm-finetuning`으로 바꿨다.
- GRPO 첫 셀의 미사용 반환값과 LoRA 셀의 미사용 `mo` 인자를 제거했다. FFN 3절 문장을 고쳤다.

## 실행 명령과 결과

```bash
cd notebooks/minimind
uv run python -m marimo check minimind_*.py            # 경고 0, rc=0 (HEAD도 0)
for f in minimind_*.py; do
  uv run python -m marimo export html "$f" -o "../../outputs/notebooks/20261110-100344-review-final/${f%.py}.html"
done                                                     # 13개 모두 rc=0, 각 5~9초
```

- `python notebook.py`와 `marimo export html` 모두 셀 예외가 발생하면 rc=1을 반환하는 것을 별도 실패 노트북으로 확인했다. 따라서 rc=0은 모든 셀의 assertion이 통과했다는 뜻이다. HTML에도 Traceback·AssertionError가 없다.
- 수정 전 기준 실행(`20261110-095133-review-baseline`)에서도 13개 모두 rc=0이었다.
- 수정 중에 marimo check 경고 3건(non-raw 문자열 안의 `\n`, `\m`)을 만들었다가 raw string으로 고쳐 0건으로 되돌렸다.

## 미실행 항목과 한계

- 모든 실행은 UI 기본값만 사용했다. 슬라이더·드롭다운의 다른 값과 과제의 코드 수정 시나리오는 실행하지 않았다.
- `marimo edit` 브라우저 편집기에서의 표시(레이아웃, mermaid, 한글 폰트)는 확인하지 않았다. HTML 내보내기만 확인했다.
- **환경 문제(수정하지 않음):** `notebooks/minimind/.venv/bin/marimo`의 shebang이 이전 경로 `notebooks/.venv/bin/python`을 가리킨다. 그래서 이 컴퓨터에서는 `uv run marimo …`가 "Failed to spawn: marimo"로 실패한다. `uv run python …`과 `uv run python -m marimo …`는 정상 동작한다. `.venv`를 삭제한 뒤 `uv sync --locked`로 다시 만들면 해결되며, 이때 의존성을 다시 내려받는다.
- 원본 프로젝트 파일(`projects/`)은 수정하지 않았다. 실제 가중치·실데이터·GPU 학습은 범위 밖이다.
- 과거 보고서 `reports/notebooks/20261109-202500-vlm-finetuning.md`가 옛 README 앵커(`#vision-llm-미세-조정-실습`)를 참조한다. 과거 기록이므로 수정하지 않았다(링크는 README 파일 자체로는 이동한다).
