## 종합 판단

작은 데이터, 원본 구현 재사용, 다음 토큰 정답 표, 학습 전후 생성 비교, 가중치 불변 검증은 유용하다. 다만 선언한 선행 지식만으로는 학생이 연산의 이유를 설명하기 어렵다. 현재 자료는 첫 입문 실습보다는 Attention·역전파·선형층을 이미 배운 학생의 구현 확인 자료에 더 가깝다. 우선 보완할 대상은 Embedding부터 출력까지의 연결, Attention의 단계 분리, LoRA의 단일 선형층 계산이다.

## 우선순위가 높은 보완점

### 1. Embedding과 LM head 사이의 연결이 빠져 있다

위치: 모델 노트북 48, 121, 174, 243행.

학생 질문: “토큰 ID는 숫자인데 어떻게 길이 32인 벡터가 되나요? LM head는 그 벡터로 단어를 어떻게 고르나요?”

Embedding 호출과 logits shape는 있지만, 사전 ID가 가중치 표의 행을 선택하는 과정과 마지막 hidden state를 어휘 점수로 바꾸는 계산을 직접 보지 못한다. 가중치 공유도 객체 일치 assertion으로만 확인한다.

개선: 한 토큰에 대해 `embedding(ids)[0, t]`와 `embedding.weight[id]`를 나란히 보여 준다. `[V,D]` 표에서 행을 고르는 입력 경로와 `[D] @ [D,V]` 출력 경로를 연결한다. 마지막 hidden state에 LM head를 직접 적용해 원본 logits와 비교한다.

### 2. Attention 한 셀에 너무 많은 새 개념이 들어간다

위치: 모델 노트북 156, 172, 179, 185, 189, 192행.

학생 질문: “Q/K/V를 만드는 이유를 배우기도 전에 왜 view와 transpose, 정규화와 회전, head 반복이 나오나요?”

Q/K/V, head 분리, QK 정규화, RoPE, GQA, 점수 계산, mask, softmax, 가중합, head 결합이 한 코드 셀에 집중되어 있다. 숫자 shape만으로는 축의 의미와 각 연산의 필요성을 추적하기 어렵다. 여러 head가 있다는 설명과 이 구현의 GQA 규칙도 빠르게 넘어간다.

개선: 먼저 한 문장·한 head의 작은 점수 행렬로 QK 내적 → 미래 가리기 → softmax → V 가중합을 확인한다. 이후 원본 구현의 다중 head, GQA, QK 정규화, RoPE를 순서대로 추가한다. 각 단계에 입력·출력 shape와 한 문장의 목적 설명을 붙인다.

### 3. Logits, 확률, 손실, 생성 반복이 연결되지 않는다

위치: 모델 노트북 227, 244, 274, 309행.

학생 질문: “손실이 줄면 왜 야옹이 나오나요? generate 한 번이 문장 전체를 만드는 건가요?”

정답 이동 표는 좋지만, 정답 토큰의 점수·확률과 cross entropy의 관계가 생략되어 있다. 생성은 원본 `generate` 호출로 처리하여 한 토큰을 뽑고 입력에 붙여 반복하는 자기회귀 과정을 직접 볼 수 없다.

개선: `고양이 는` 뒤 후보의 logits와 softmax 확률을 학습 전후 표로 표시한다. 한 위치의 정답 손실 `-log(p_target)`를 평균 cross entropy에 연결한다. `argmax → 토큰 추가 → 다음 forward → eos 종료`를 몇 줄의 별도 실습으로 보여 준다.

### 4. LoRA의 핵심 수식이 실제 행렬 계산으로 이어지지 않는다

위치: LoRA 노트북 194, 215, 224, 238행. 원본 `model_lora.py` 6, 17, 29행.

학생 질문: “A와 B가 작은 행렬이라는 건 알겠는데, rank가 정확히 무엇을 제한하나요? 원래 W가 사라지나요?”

수식과 shape 표는 있지만, 실제로는 `apply_lora` 호출이 동작을 감춘다. 학습 대상 수가 줄어든 것과 모델 전체 매개변수가 줄어든 것을 혼동할 여지가 있다. ‘d² 대신 2dr’라는 표현에는 원본 W를 계속 보유한다는 설명을 붙여야 한다.

개선: 단일 Linear로 `Wx`, `Ax`, `B(Ax)`, 합산 출력을 보여 준다. d=32, r=4일 때 원본 W 1,024개는 보존되고 A/B 256개가 추가되며 이 256개만 학습됨을 표로 비교한다. 일반적인 직사각형 가중치의 A `[r,in]`, B `[out,r]`, ΔW `[out,in]`도 설명하여 정사각형만 지원하는 현재 적용 함수와 구분한다. rank는 ΔW의 rank 상한이며 실제 rank와 항상 같지는 않다는 점을 짧게 적는다.

### 5. 동결과 역전파가 관찰 가능한 실습으로 설명되지 않는다

위치: 모델 노트북 274, 289행, LoRA 노트북 220, 254, 262행.

학생 질문: “W를 동결했는데 어떻게 A/B까지 학습 신호가 전달되나요? eval이면 학습이 안 되나요?”

`requires_grad_(False)`, `no_grad`, `eval`, `backward`, optimizer의 역할 차이가 선행 지식으로 암묵적으로 요구된다. ‘Python 함수와 shape면 된다’는 안내와 실제 요구 수준이 맞지 않는다. 전체 학습 순서 설명도 명령 나열에 머문다.

개선: 한 번의 backward 전후에 W/A/B의 `requires_grad`, `grad` 존재 여부·norm, 가중치 변화량을 표시한다. B가 0인 초기 상태에서 첫 backward의 A gradient는 0일 수 있고 B는 학습될 수 있음을 관찰한다. 동결은 역전파 전체를 끄는 것과 다름을 설명한다. `eval`은 gradient 비활성화와 별개의 기능임을 짧게 구분한다.

## 다음 순서로 보완할 점

### 6. Attention 시각화가 문장 이해로 이어지기 어렵다

위치: 모델 노트북 199행.

현재 그림은 학습 전의 첫 head이고 축은 위치 번호다. 학생은 어느 단어가 어느 단어를 보는지 읽기 어렵다. causal mask 확인에는 유용하지만 학습된 관계를 보여 주는 그림은 아니다.

개선: 축에 실제 토큰을 표시하고, 예를 들어 ‘는 위치의 query가 고양이 위치의 key를 본다’를 짚는다. 학습 후 동일 문장·head를 비교한다. Attention 확률을 모델 판단의 완전한 인과 설명으로 단정하지 않도록 한다.

### 7. 실습의 성공 기준과 해설이 부족하다

위치: 모델 노트북 368행, LoRA 노트북 336행.

과제는 있지만 예상 관찰, 실패했을 때 확인할 부분, 힌트나 해설이 없다. 최종 assertion 통과는 수강생의 개념 이해를 확인하지 못한다. rank를 바꾸어도 네 문장이 모두 맞으면 학생이 차이를 해석하기 어렵다.

개선: 각 절을 ‘예측 → 실행 → 관찰 → 설명’으로 구성한다. 예를 들어 KV head를 2→4로 바꾸기 전에 K shape를 쓰게 하고 실행 후 비교한다. rank 과제에서는 정답률 외에 학습 대상 수·손실·변화 행렬 크기를 함께 기록하게 한다. 손실 감소와 문장별 정답 여부를 구분하는 판정표를 제공한다.

### 8. 저랭크와 메모리·저장 이점의 범위를 구분해야 한다

위치: LoRA 노트북 195, 236, 302행.

학습 매개변수 비율만으로 전체 모델 메모리나 추론 메모리까지 같은 비율로 줄었다고 이해할 수 있다. LoRA 전후 새 정답 비교는 행동 변경을 보여 주지만 일반화나 전체 미세 조정 대비 성능을 입증하지 않는다. 일반화 한계 안내는 이미 있으므로 이를 유지하면 된다.

개선: ‘원본 가중치 보유량 / 학습 대상 / 어댑터 파일 / 병합 모델’의 네 항목을 구분한다. 파일 크기를 직접 표시하되 같은 dtype과 직렬화 오버헤드를 고려한다. 이번 작은 실습에서는 학습 시간·메모리 절감의 실제 규모를 측정하지 않았음을 명시한다.

### 9. marimo에서 코드를 고치는 방법의 안내가 짧다

위치: 모델 노트북 57행과 두 파일의 긴 함수 인자·return 목록.

초보자는 `@app.cell`, 셀 함수의 인자·return, `_`로 시작하는 중간 변수와 반응형 재실행 규칙을 모델 구현의 일부로 혼동할 수 있다. 코드를 한 단계씩 수정하는 실습을 하려면 별도 안내가 도움이 된다.

개선: 첫머리에 ‘바꿀 곳은 config·샘플·핵심 연산’, ‘셀 간 전달은 인자·return’, ‘이 노트북은 독립 실험을 위해 모델을 매번 새로 복사’하는 규칙을 설명한다. 고급 초기화·복사·검증 코드는 설명을 접거나 부록으로 옮겨 핵심 계산에 집중하게 한다.
