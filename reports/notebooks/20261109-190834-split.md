## 변경 내용

기존 `minimind_structure_lora.py`를 두 파일로 대체했다. 모델 노트북은 데이터·구조·전체 학습·생성·KV cache와 모델 과제를 포함한다. LoRA 노트북은 기준 모델 준비·동결·어댑터 적용과 학습·생성 비교·저장·복원·병합과 LoRA 과제를 포함한다. 설명 번호, 제목, UI와 import를 각각의 범위에 맞췄고 README의 파일 링크와 명령을 갱신했다.

LoRA는 다른 노트북을 import하거나 실행 결과에 의존하지 않는다. 자체 샘플과 초기화·100 step 전체 학습으로 기준 모델을 준비한다. 이 준비 단계와 이후 LoRA 학습을 설명에서 구분했다. 원본 `minimind/model/model_minimind.py`, `model_lora.py`는 수정하지 않았다.

외부 체크포인트와 데이터 리비전은 없다. 기존 네 문장 데이터, 모델 초기화 seed 42와 LoRA seed 7을 유지했다. 모델은 hidden size 32, 2층, Q head 4개, KV head 2개, intermediate size 64이며, 모델 학습률 0.005, LoRA 학습률 0.01, 기본 rank 4이다.

## 실행과 판정

작업 디렉토리 `notebooks/`에서 다음 명령을 실행했다. 실행 시 환경 변수 `XDG_CONFIG_HOME=/tmp/minimind-marimo-config`, `MPLCONFIGDIR=/tmp/minimind-marimo-mpl`, `MPLBACKEND=Agg`를 사용했다.

```bash
.venv/bin/marimo check minimind_structure.py minimind_lora.py --strict --format json
.venv/bin/python minimind_structure.py
.venv/bin/python minimind_lora.py
```

- marimo strict 검사: 두 파일, 문제 0개. `check.json`에 저장했다. 검사기의 비동기 실행에 필요한 로컬 소켓을 허용하여 실행했다.
- 별도 Python 프로세스로 두 파일의 전체 셀을 각각 실행: 모두 종료 코드 0. `model-script.log`, `lora-script.log`에 기록했다.
- 저장소 루트에서 각 파일을 `importlib`로 읽어 `app.run()`으로 전체 셀을 실행하고, `complete` 함수 결과를 네 문장의 정답 문자열과 직접 비교했다. 지표는 `metrics.json`, 출력은 `execution.log`에 보관했다.
- 모델: 전체 학습 최종 손실 0.239934, 원래 정답 생성 4/4, KV cache 최대 오차 0.
- LoRA: 기준 모델의 원래 정답 생성 4/4, 어댑터 학습 후 새 정답 생성 4/4. 새 정답 최종 손실 0.242767, 복원 최대 오차 0.001121, 병합 최대 오차 0.005561.
- 기존 내장 assertion(Attention·블록·손실 일치, 패딩, causal mask, 원본 가중치 불변, 어댑터 변경, 저장·복원·병합)도 해당 노트북에서 모두 통과했다.
- Python 구문, 줄 끝 공백, README의 로컬 링크와 통합 파일 제거를 확인했다.
