# 공통 평가 규칙 — 지표 버전 2.0

공통 작업 규칙
- 저장소와 대상 경로의 AGENTS.md, 실습 README, 환경 설정, 대상 노트북, 가져오는 실제
  구현을 읽는다. marimo .py도 노트북이다. 프로젝트 경계와 동명 model 모듈을 구분한다.
- 입력은 대상 경로, 학습자 수준, 목표, 수업 시간, 환경, 교재 범위다. 대상이 없으면
  경로를 요청한다. 나머지는 README에서 확인하고 없으면 가정을 명시한다.
  기본 독자는 Python 함수·기초 텐서 연산을 알지만 해당 모델을 처음 배우는 입문자다.
- 기본은 정적 검토다. 소스·환경 설정을 수정하지 않으며 노트북 전체 실행, 학습,
  다운로드, 설치, 클라우드 생성은 평가 요청만으로 시작하지 않는다.
- 실행을 요청받은 경우 프로젝트 환경에서 수행하고 명령·작업 디렉토리·환경/패키지 버전·
  모델/데이터 리비전·실패·미실행·한계를 기록한다. 정적 분석, 구문 검사, 작은 실행,
  전체 학습, 화면 확인을 구분한다. 과거 보고서만으로 현재 실행 성공을 주장하지 않는다.
- 실제 수강생 조사, 실제 수업 관찰, 원저자의 의도를 대변하지 않는다.
  다른 평가자의 결과를 읽기 전에 독립 평가하고 사실·추정·미확인을 구분한다.
- 각 지적에 파일:행과 절/셀, 근거, 학습 영향, 수정안, 완료 조건을 붙인다.
  누락의 근거는 있어야 할 절과 확인한 범위를 적는다. 취향이나 문제 개수로 감점하지 않는다.
- 공식 문서·원논문 확인이 필요하면 실제 읽은 버전·장·절·쪽 또는 URL을 근거로 남긴다.
  확인하지 못한 출처나 읽지 않은 PDF·도식의 내용을 만들어내지 않는다.


평가 계약과 절별 집계 (지표 버전 2.0)
- 평가 전에 통합 담당이 고정한 평가 계약을 읽는다. 계약은 독자·목표·선수 지식·필수/심화
  범위, 대상 및 참조 구현의 파일 해시, 핵심 절/개념/함수 목록, 80개 항목별 적용 단위와
  핵심 여부, 실행 범위, 필요한 검증을 담는다. 예시는 ../assets/contract-template.json을 참고한다.
- 단독 평가이고 계약이 없으면 같은 필드를 먼저 채워 보고서에 명시한다. 여러 역할의
  독립 평가에서는 공통 계약 없이는 채점을 시작하지 않는다. 불완전한 템플릿은 계약이 아니다.
- 이론·적용 범위에 대한 이견은 범위 변경 제안으로 따로 기록한다. 평가 중 임의로 목표나
  해당 없음 목록을 바꾸지 않는다. 독립성은 판단에 적용하며 공통 범위까지 다르게 정하지 않는다.
- 각 항목은 계약에서 지정한 모든 절/개념/함수에 대해 개별 판정한다. 한 단위라도 미충족이면
  항목 전체는 미충족, 미충족 없이 미확인이 남으면 미확인, 모두 통과하면 통과다.
  해당 없음은 사전에 정한 적용 제외에만 사용한다. 일부 절의 좋은 예로 전체 통과하지 않는다.
- 항목마다 단위별 근거와 잔여 누락을 제공하고, 핵심 여부는 평가 후 점수에 맞춰 바꾸지 않는다.
- 수정 전후 동일한 계약·지표 버전·적용 단위·참조 구현으로 비교한다. 대상 수정본의 새 해시와
  원본 대비 diff를 남긴다. 범위/참조 구현/지표가 바뀌면 계약 버전을 올리고 별도 기준선으로
  재평가한다. 이전 점수와의 직접 증감 비교를 금지한다.

공통 점수화 규칙
- 아래 5개 지표는 각각 20점, 총 100점이다. 지표마다 4개의 판정 항목이 있다.
  모든 항목을 통과 / 미충족 / 미확인 / 해당 없음으로 판정하고 근거 위치와 이유를 적는다.
- 통과는 설명·코드·예시 등으로 조건이 충족됨을 확인한 경우다. 있어야 할 설명이 없으면
  미충족이다. 파일·교재 접근 불가 등으로 확인할 수 없으면 미확인이다.
  실제 실행하지 않았다는 이유만으로 정적으로 확인 가능한 설명 항목을 미확인 처리하지 않는다.
- 해당 없음은 목표상 불필요한 항목에만 쓰고 이유를 적는다. 핵심 설명의 누락이나
  원본 코드 접근 실패를 해당 없음으로 제외하지 않는다. 짧은 글·많은 수식 자체는 가감점하지 않는다.
- 지표별 p=통과 수, f=미충족 수, u=미확인 수, n=p+f+u(해당 없음 제외)로 둔다.
  n>0인 지표의 관측 점수는 5*p/(p+f), 확인률은 (p+f)/n이다.
  p+f=0이면 점수는 N/A이며 0점을 부여하지 않는다. n=0이면 적용 제외다.
- 적용되는 지표 수를 k라 하면 지표의 환산 가중치는 w=100/k다(기본 20점).
  C=sum(w*(p+f)/n)/100, P=sum(w*p/n), U=sum(w*u/n)로 계산한다.
  관측 총점=P/C(단 C>0), 보수적 하한=P, 가능한 상한=P+U다.
  모든 지표가 적용 제외면 총점은 N/A다. 중간 계산은 반올림하지 않고 표시는 소수 첫째 자리로 한다.
- C=100%일 때만 확정 총점으로 표시한다. 미확인이 있으면 관측 총점은 잠정이며
  확인률·하한~상한을 함께 적는다. 최종 판정은 아래 순서와 핵심 항목 규칙을 적용한다.
- 지표 표: ID / 지표 / 가중치 / p,f,u,해당 없음 수 / 0~5점 / 확인률 / 근거.
  전체 20개 판정 항목도 ID(예: S1.1), 상태, 근거와 함께 제공한다.
- 심각도는 치명(진행 불가·핵심 개념 오류), 주요(목표 달성 방해), 개선(보완 가능)이다.
  동일한 결함이 다른 지표도 실패시키면 각 항목의 영향 근거를 적고 별도 벌점을 더하지 않는다.
- 사용 판정은 관측 총점이 아니라 점수 하한 P와 핵심 항목으로 정한다. C는 0~1 값이며
  확인률 80%는 C=0.8이다. 다음 순서를 적용한다.
  1) 확인된 치명 결함 또는 미해결 주요 결함이 있으면 수정 후 사용이다. 핵심 항목의
     미충족은 최소 주요 결함이다. 함께 남은 미확인·검증 한계도 별도로 표시한다.
  2) 적용 지표 없음, C<0.8, 필수 비교 근거 부재 또는 핵심 항목 미확인이면 판단 보류다.
  3) 위 조건이 없고 P>=85이면 정적 검토상 사용 가능이다.
  4) P+U<85이면 수정 후 사용, 그 외에는 판단 보류다.
  사용 가능이어도 비핵심 미확인·실행 미검증은 남겨야 한다. 점수 확정과 실제 실행 검증은
  별개다. 기준은 교육 자료 개선용 내부 기준이며 검증된 학습 효과 척도로 주장하지 않는다.

출력 순서
1. 계약 ID·지표 버전·기준선/수정본 해시·범위·독자/수업 조건·검증 수준·미확인 사항.
2. 심각도순 발견: [심각도][발견 ID] 위치 / 근거 / 영향 / 수정안 / 완료 조건.
3. 단위별 근거를 포함한 전체 판정 항목과 5개 지표 점수표, 총점(잠정/확정), 확인률, 점수 범위.
4. 역할별 추가 산출물, 유지할 장점, 우선 수정 최대 3개. 재평가면 발견 ID별 해결/부분 해결/미해결·새 결함과 전후 근거.
5. 정적 검토상 판정: 사용 가능 / 수정 후 사용 / 판단 보류와 판정 이유.
   소스 분석 결과를 실행 준비 완료 또는 실제 학습 효과로 표현하지 않는다.


점수 계산·판정은 ../scripts/review.py score를 사용한다.
