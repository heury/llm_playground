# 실습 노트북 평가·업데이트

아래 경로는 이 Skill 폴더 기준이다. 저장소 산출물 경로는 작업 중인 저장소 루트 기준이다.

## 모드와 범위

- **평가:** 진단·점수·개선안을 작성한다. 평가 요청만으로 소스를 수정하지 않는다.
- **업데이트:** 평가 결과를 통합하여 한 담당자가 수정·필요 검증·재평가를 수행한다.
- **부분 검토:** 작은 문구 수정 등은 관련 관점만 사용한다. 네 관점 전체를 실행했다고 말하거나
  전체 100점 평가로 포장하지 않는다. 전체 채점은 네 역할·80개 항목이 필요하다.

대상 경로가 없으면 요청한다. 독자·목표·선수 지식은 사용자 지시와 대상 README에서 정하고
추론한 부분은 가정으로 기록한다. AGENTS.md와 프로젝트별 환경·산출물 규칙을 적용한다.

## 평가

1. [공통 평가 규칙](references/rubric.md)을 읽는다. 전체 평가 또는 업데이트에서는
   [운영 절차](references/workflow.md)에 따라 공통 계약을 완성한다.
   [계약 템플릿](assets/contract-template.json)은 빈 시작점이며 완성된 계약이 아니다.
   실제 참조 구현을 추적한다. projects/ 기반은 그 프로젝트를, 독립 구현·외부 패키지는
   실제 사용하는 구현을 비교한다. 파일 해시와 핵심 단위·항목별 적용/제외·핵심 여부를 고정한다.
2. `python3 scripts/review.py validate-contract <계약.json> --root <저장소>`로
   계약 구조와 기준선 파일 해시를 검사한다. 오류를 해소하고 동일 파일 상태를 평가한다.
3. 관련 역할 정의를 읽어 적용한다:
   [학생](references/roles/student.toml), [선생님](references/roles/teacher.toml),
   [편집자](references/roles/author.toml), [연구자](references/roles/researcher.toml).
   전체 평가에서는 네 관점을 독립 평가하는 subagent를 사용하고 동시 실행 한도에 맞춰 나눈다.
   각 subagent에 역할 파일·공통 규칙의 실제 경로·같은 계약·대상 파일 상태를 전달한다.
   위임을 사용할 수 없으면 순차 관점 검토임을 명시하고 독립 세션을 실행했다고 주장하지 않는다.
   부분 검토에서는 필요한 관점만 주 Agent가 적용해도 된다.
4. 항목·단위별 판정과 근거를 [평가 JSON 형식](references/result-format.md)으로 저장한다.
   `python3 scripts/review.py score <계약.json> <평가.json> --root <저장소>`으로 계산한다.
   관측 점수는 진단용이며 사용 판정은 하한·핵심 미확인·미해결 주요 결함을 따른다.
   스크립트는 근거의 의미적 진실성이나 실제 학생 이해를 검증하지 않는다.

## 업데이트

평가만 요청되었다면 여기서 마친다. 업데이트 요청이면 [운영 절차](references/workflow.md)의
수정·검증·재평가를 따른다. 다른 작업자의 변경을 덮어쓰지 않고 기준선 사본을 보존한다.

- 발견 ID별 채택/보류/기각·이유·수정 위치·완료 조건을 정하고 한 담당자가 수정한다.
  필수 이론과 읽기 부담이 충돌하면 본문에 필요한 설명을 남기고 심화를 분리한다.
- 변경 종류에 맞게 링크·수식/코드 대응·화면·marimo 셀 의존성·작은 계산을 검증한다.
  현재 요청 범위를 넘는 전체 학습·다운로드·설치·클라우드 생성은 시작하지 않는다.
  필요한 검증을 못 하면 이유와 영향을 기록한다. 이미 허용된 가역적 작업을 반복 승인받지 않는다.
- 같은 계약·적용 단위·참조 구현·지표 버전으로 수정본을 재평가한다. 수정본 해시는 계약의
  `after_files`에 별도 기록하며 `validate-contract --phase after`로 검사한다.
  평가 JSON의 `phase`도 `after`로 한다. 실제 참조 파일은 두 단계 모두 같은 해시여야 한다.
  범위가 바뀌면 계약 버전을 올려 새 기준선을 만들고 이전 점수와 직접 증감 비교하지 않는다.
- 수정본을 먼저 독립 채점한 다음 이전 발견과 대조해 해결/부분 해결/미해결·새 결함을 남긴다.
  편집 후 의미 보존은 현재 E5 점수와 별도로 원문·수정본 diff에서 확인한다.
- 치명 오류 없음, 목표를 막는 주요 결함 해결, 핵심 미확인 없음, 필요 검증 완료를
  확인해야 완료라고 보고한다. 점수 상승만을 종료 조건으로 삼지 않는다.

## 결과 저장

한국 시각의 공통 실행 ID를 사용한다. 계약·전후 평가·수정 목록·검증·한계는
`reports/<프로젝트>/<실행 ID>-*.{json,md}`, 기준선·diff·해시·로그는
`outputs/<프로젝트>/<실행 ID>/`에 저장한다. 기존 MiniMind 실습의 프로젝트명은 `notebooks`다.
명령·작업 디렉토리·환경/패키지·모델/데이터 리비전·실패/미실행·산출물 경로를 보고한다.
