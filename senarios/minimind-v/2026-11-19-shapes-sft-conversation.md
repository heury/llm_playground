## 어시스턴트

처음에는 **합성 이미지로 색상·도형을 답하게 하는 시나리오**를 추천합니다. 데이터를 직접 만들 수 있고, 정답이 명확해서 학습 전후를 비교하기 쉽습니다.

| 시나리오 | 입력과 질문 | 정답 예시 | 난이도 |
|---|---|---|---|
| **색상·도형 인식** | 빨간 원 이미지 + “색과 모양은?” | `red circle` | 쉬움 |
| 좌우 위치 판단 | 파란 원과 빨간 사각형 + “원의 위치는?” | `left` | 보통 |
| 물체 개수 세기 | 원 1~3개 + “몇 개인가요?” | `2` | 보통 |
| 로봇 장면 상태 판단 | 시뮬레이터 이미지 + “블록이 목표 영역 안에 있나요?” | `yes` | 응용 |

첫 실험은 다음처럼 구성하면 좋습니다.

**1. 색상 3개 × 도형 2개로 데이터를 만듭니다.**

- 색상: 빨강·초록·파랑
- 도형: 원·사각형
- 흰 배경에 도형 하나를 그리고, 위치와 크기를 무작위로 변경
- 제안 규모: 학습 600장, 검증 120장, 테스트 120장
- 같은 이미지가 여러 분할에 들어가지 않도록 생성

답변은 `red circle`, `blue square`처럼 **6개 조합으로 제한**합니다. 첫 실험은 짧은 영어 답변을 사용하면 한국어 표현 능력과 시각 인식을 나누어 확인하기 쉽습니다.

**2. 기존 VLM 체크포인트에서 작은 SFT를 수행합니다.**

이미 학습된 `sft_vlm` 가중치에서 시작하고, 먼저 `--freeze_llm 2`로 **Projector만 학습**하는 구성을 권합니다. 성능 향상이 부족하면 `--freeze_llm 1`로 Projector와 LLM 첫 층·마지막 층을 함께 학습합니다.

처음부터 무작위 Projector를 정렬하는 실험보다, 기존 VLM에 작은 과제를 추가하는 편이 짧은 학습의 효과를 확인하기 좋습니다.

현재 [데이터 로더](../../projects/minimind-v/dataset/lm_dataset.py#L49)는 **이미지 바이트와 대화가 들어 있는 Parquet**를 읽습니다. 한 행은 개념적으로 다음과 같습니다.

```python
{
    "image_bytes": [png_bytes],
    "conversations": [
        {"role": "user", "content": "<image>\nWhat color and shape is it?"},
        {"role": "assistant", "content": "red circle"},
    ],
}
```

`<image>`는 로더가 모델의 시각 토큰 자리표시자로 바꿉니다.

**3. 학습 전후를 같은 테스트셋으로 비교합니다.**

생성은 샘플링을 끄고 평가하며, 다음을 확인합니다.

| 평가 | 확인할 내용 |
|---|---|
| 색상 정확도 | 색을 맞히는가 |
| 도형 정확도 | 모양을 맞히는가 |
| 조합 정확도 | `red circle` 전체를 맞히는가 |
| 이미지 교체 검사 | 질문을 고정하고 이미지를 바꾸면 답도 맞게 바뀌는가 |
| 위치·크기 변화 | 학습 이미지의 배치만 외운 것은 아닌가 |

예를 들어 **조합 정확도 90% 이상**을 실험 목표로 정할 수 있습니다. 이는 예상 성능을 보장하는 수치는 아닙니다. 학습 전부터 높게 나온다면, 일부 색상·도형 조합을 학습에서 제외하고 테스트하는 방식으로 난도를 올릴 수 있습니다.

현재 로컬에서는 필요한 비전 인코더와 VLM 가중치의 존재를 확인하지 못했습니다. 실제 실행에는 이 리소스가 필요합니다. GPU 없이 학습 경로만 확인하려면 기존 [기능 실습](../../projects/minimind-v/exercise/README.md)의 Projector 업데이트 예제를 사용할 수 있지만, 이는 이미지 인식 성능을 검증하는 실험과는 구분해야 합니다.
