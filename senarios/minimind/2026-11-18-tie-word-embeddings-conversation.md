# MiniMind tie_word_embeddings 대화 원본

## 사용자

minimind에서 **tie_word_embeddings=True를 하면 어떤 효과가 있는지 설명해**

## 어시스턴트

`tie_word_embeddings=True`는 **입력 토큰을 벡터로 바꾸는 가중치와, 다음 토큰을 예측하는 가중치를 하나로 공유하는 설정**입니다.

MiniMind에는 다음 두 부분이 있습니다.

```text
입력 토큰
   ↓
embed_tokens: 토큰 번호 → 벡터
   ↓
Transformer
   ↓
lm_head: 벡터 → 어휘별 점수
   ↓
다음 토큰 선택
```

**1. 입력과 출력이 같은 가중치를 사용합니다.**

기본 설정에서 두 가중치의 크기는 같습니다.

| 부분 | 가중치 크기 |
|---|---|
| `embed_tokens` | 어휘 6,400 × 벡터 차원 768 |
| `lm_head` | 어휘 6,400 × 벡터 차원 768 |

`False`이면 각각 별도로 학습합니다. `True`이면 MiniMind의 [이 코드](/home/mind4u/dev/llm_playground/projects/minimind/model/model_minimind.py:250)가 둘을 연결합니다.

```python
if self.config.tie_word_embeddings:
    self.model.embed_tokens.weight = self.lm_head.weight
```

가중치를 복사하는 것이 아니라 **동일한 매개변수를 함께 참조**합니다. 한쪽 가중치가 업데이트되면 다른 쪽에도 그대로 반영됩니다.

**2. 같은 토큰 벡터를 ‘읽기’와 ‘예측하기’에 활용합니다.**

예를 들어 “학교” 토큰의 벡터를 생각하면 다음과 같습니다.

```text
입력: “학교” 토큰이 들어오면
      → 공유 가중치에서 “학교” 벡터를 꺼냄

출력: 다음 토큰을 예측할 때
      → 최종 벡터와 “학교” 벡터의 내적으로 “학교”의 점수를 계산
```

공유 가중치를 `E`라고 하면:

```python
입력 벡터 = E[토큰 번호]
출력 점수 = 최종 벡터 @ E.T
```

학습 중에는 입력 역할과 출력 역할에서 발생한 기울기가 **같은 가중치에 합쳐집니다.**

**3. 매개변수와 메모리가 줄어듭니다.**

MiniMind 기본 설정에서는 행렬 하나를 줄입니다.

```text
6,400 × 768 = 4,915,200개
```

즉, **약 492만 개의 매개변수를 절약**합니다. FP32 가중치만 계산하면 약 **18.75MiB**입니다. 전체 미세 조정에서는 이 행렬에 필요한 기울기와 Adam 상태도 중복해서 보관하지 않으므로 추가로 절약됩니다.

입력과 출력이 같은 토큰 표현을 사용하도록 제약하는 효과도 있지만, 정확도가 항상 높아지는 것은 아닙니다. **MiniMind에서는 기본값이 `True`이며, 앞서 측정한 LoRA 메모리 실험도 이 설정을 사용했습니다.**

## 사용자

`embed_tokens`과 `lm_head`의 가중치가 왜 같은지 설명해

## 어시스턴트

두 가중치가 같은 이유는 **모두 ‘어휘의 각 토큰에 대응하는 벡터’를 가지고 있기 때문**입니다. 원래부터 값이 같은 것은 아니고, `tie_word_embeddings=True`가 같은 가중치를 사용하도록 연결합니다.

예를 들어 어휘가 3개이고 벡터 차원이 2라고 해보겠습니다.

```text
             공유 가중치 E
“나는”       [0.2, 0.8]
“학교”       [0.9, 0.1]
“간다”       [0.4, 0.6]
```

**`embed_tokens`는 이 표에서 토큰의 벡터를 꺼냅니다.**

```text
입력 토큰 “학교”
      ↓
“학교” 행 선택
      ↓
[0.9, 0.1]
```

**`lm_head`는 Transformer의 최종 벡터와 표의 모든 행을 비교합니다.**

최종 벡터가 `[1.0, 0.0]`이라면 내적 점수는 다음과 같습니다.

```text
“나는” 점수 = [1.0, 0.0] · [0.2, 0.8] = 0.2
“학교” 점수 = [1.0, 0.0] · [0.9, 0.1] = 0.9
“간다” 점수 = [1.0, 0.0] · [0.4, 0.6] = 0.4
```

이 경우 “학교”의 점수가 가장 높습니다. 이 점수들에 softmax를 적용하면 다음 토큰의 확률이 됩니다.

따라서 같은 표를 두 방향으로 활용할 수 있습니다.

| 역할 | 같은 가중치를 사용하는 방식 |
|---|---|
| `embed_tokens` | 토큰 번호로 **행 하나를 선택** |
| `lm_head` | 최종 벡터와 **모든 행을 내적** |

MiniMind에서는 둘 다 가중치 모양이 `[어휘 크기, 벡터 차원]`이므로 공유할 수 있습니다. `lm_head`의 계산은 내부적으로 `h @ E.T`가 됩니다.

다만 **모양이 같다고 반드시 공유해야 하는 것은 아닙니다.** 공유하지 않으면 ‘입력을 표현하는 벡터’와 ‘출력 토큰을 판별하는 벡터’를 따로 학습합니다. 공유하면 두 역할에 같은 벡터를 쓰도록 제약하면서 매개변수를 줄입니다.
