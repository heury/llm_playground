## 어시스턴트 — 시나리오 추천

### 추천: "교사를 먼저 특화한 뒤, 정답이 적을 때 학생에게 증류"

현재 저장소에서 확인한 사실이 하나 있습니다. 기존 증류 실행([reports/notebooks/20261113-132831-distillation-tour.md](../../../reports/notebooks/20261113-132831-distillation-tour.md))에서 GSM8K 기준 교사 CE는 1.257, 학생 CE는 1.240이었습니다. **교사가 학생보다 낫지 않았습니다.** 두 모델은 같은 데이터로 SFT됐고 토큰마다 쓰는 매개변수도 약 64M으로 같습니다. 그래서 공개 체크포인트를 그대로 쓰면 지식 전달 효과가 나타나지 않습니다. 시나리오를 짤 때 **교사가 더 나은 상황을 먼저 만들어야 합니다.**

#### 시나리오: 짧은 정답 하나를 고르는 분류 과제 (예: 감정 3분류, 주제 4분류)

| 단계 | 내용 |
|---|---|
| 0. 데이터 | 답변이 한 단어인 과제를 고릅니다. 예: "다음 문장의 감정은? → 긍정/부정/중립". 데이터를 교사 학습용 라벨 2,000개, **학생용 라벨 200개**, 라벨을 쓰지 않는 질문 2,000개, 평가용 300개로 나누고 서로 겹치지 않게 합니다. |
| 1. 교사 특화 | MoE 교사를 라벨 2,000개로 짧게 SFT해서 평가 정확도가 학생보다 확실히 높은지 먼저 확인합니다. **이 차이가 없으면 다음 단계로 가지 않습니다.** |
| 2. 비교 실험 | 학생(Dense 64M)을 똑같은 step 수로 세 가지 방식으로 학습합니다. ① **CE만**: 라벨 200개 ② **KD**: 라벨 200개에 CE와 KL을 섞음 (`alpha=0.5, T=2`) ③ **KD와 라벨 없는 질문**: ②에 라벨 없는 2,000개를 더하고, 이 질문들은 KL만 씀 (`alpha=0`) |
| 3. 판정 | 평가 정확도, 교사와 1등 답이 일치하는 비율, 정답 토큰 CE와 확률 보정(ECE)을 봅니다. ③이 ①보다 뚜렷하게 높으면 지식이 전달된 것입니다. ②와 ①의 차이는 soft label이 규제 효과를 내는지 보여 줍니다. |

**이 시나리오를 추천하는 이유**
- **정확도로 바로 판정됩니다.** 답이 한 토큰이라 생성 결과를 사람이 읽고 채점할 필요가 없습니다. GSM8K는 두 모델 모두 정답률이 약 1%라 이 판정이 불가능했습니다.
- **"dark knowledge"가 눈에 보입니다.** 예를 들어 교사가 "중립 0.6, 긍정 0.3"처럼 애매함을 확률로 표현하는 것을 기존 노트북의 온도 슬라이더처럼 바로 보여 줄 수 있습니다.
- **증류를 쓰는 실제 이유를 재현합니다.** 라벨은 비싸고 라벨 없는 입력은 많은 상황입니다. ③은 원본 `train_distillation.py`의 손실 식에서 `alpha`만 데이터별로 다르게 주면 되므로 코드를 거의 고치지 않아도 됩니다.
- **비용이 작습니다.** 기존 측정에서 학생 1 step은 47ms, 교사 순전파는 36ms, 최대 메모리는 3.6GB였습니다. RTX 3080 Ti 한 장으로 실험 하나가 몇 분 안에 끝납니다.

#### 다른 선택지

1. **상품 지식 SFT 교사 → 학생** (`projects/minimind/scripts/knowledge_sft/`를 재사용): 교사에게만 새 사실을 가르친 뒤 학생에게 증류합니다. "학생이 본 적 없는 지식이 전달되는가"를 보여 주기에는 좋습니다. 다만 사실 지식은 같은 질문 형태로만 전달되기 쉽고, 답을 바꿔 쓴 질문으로는 잘 일반화되지 않을 수 있습니다.
2. **Sequence-level KD**: 교사가 greedy로 생성한 답변을 정답처럼 써서 학생을 SFT합니다. logit 없이도 되는 방식이라 1번 시나리오의 대조군으로 함께 돌리면 비교가 됩니다.
3. **교사를 특화하지 않고 일반 대화 데이터로 증류**: UltraChat 프로토타입에서 CE 차이가 1.506 대 1.572로 작았습니다. 효과가 잘 보이지 않으므로 추천하지 않습니다.

## 어시스턴트 — 진행 설명

- "1번 시나리오"는 처음 추천한 라벨 부족 분류 과제로 이해했습니다.
- 데이터셋은 영어 6클래스 감정 데이터 `dair-ai/emotion`(리비전 `cab853a1…`)으로 정했습니다. 기반 모델이 영어 중심이기 때문입니다.
- MoE 스냅샷에는 토크나이저가 없어 같은 어휘(6400)의 Dense 토크나이저를 공용으로 썼습니다.
- 라벨이 여러 토큰으로 나뉘고 첫 토큰이 겹치므로(sadness와 surprise 모두 118로 시작), 평가는 6개 후보 각각의 `라벨+EOS` 로그확률 합을 비교하는 방식으로 했습니다.
- 실행 전에 판정 기준을 시나리오 문서에 고정했습니다. S4(교사 hard label)와 S5(실제 라벨 2,000개 상한)를 대조군으로 추가했고, 학생 실험은 seed 3개로 반복했습니다.
- 실행: `projects/minimind/`에서 `.venv/bin/python scripts/knowledge_sft/kd_classification.py --output ../../outputs/minimind/20261119-081738-kd-classification` (약 398초, 최대 GPU 5.3GB)

## 어시스턴트 — 결과 보고

라벨 부족 감정 분류 시나리오로 학습을 끝냈습니다. 미리 정한 판정 기준 4개를 모두 통과했습니다. 다만 정확도 향상의 대부분은 soft label이 아니라 교사가 라벨 없는 문장에 붙여 준 라벨에서 나왔습니다.

**구성**
- 데이터: 영어 6클래스 감정 데이터셋 `dair-ai/emotion`
- 교사: MoE 모델을 라벨 2,000개로 먼저 학습
- 학생: 라벨 200개와 라벨 없는 문장 2,000개로 다섯 가지 방식(S1~S5)을 비교. 방식마다 seed 3개로 반복
- 평가: test 2,000문항 (RTX 3080 Ti 한 장, 약 7분)

| 모델 | 정확도 | NLL | ECE |
|---|---|---|---|
| 학생 학습 전 (모든 문항을 sadness로 답함) | 29.1% | 2.97 | 0.64 |
| 교사 SFT (라벨 2,000개) | 88.1% | 0.38 | 0.07 |
| S1 라벨 200개, CE만 | 67.3 ± 1.4% | 1.91 | 0.23 |
| S2 라벨 200개, CE + KD | 69.8 ± 0.4% | 0.99 | 0.14 |
| **S3 S2 + 라벨 없는 2,000개에 KD** | **86.9 ± 0.3%** | **0.40** | **0.06** |
| S4 같은 데이터, 교사의 hard label로 CE | 86.6 ± 0.2% | 0.55 | 0.09 |
| S5 실제 라벨 2,000개 (상한) | 88.2 ± 0.1% | 0.35 | 0.05 |

**해석**
- **정확도:** 정답 라벨 200개만 쓴 S3가 실제 라벨 2,000개를 쓴 S5 정확도의 98.5%에 도달했습니다.
- **soft label의 몫:** S3(soft)와 S4(hard)의 정확도 차이는 0.3%p로 seed 편차 수준입니다. 그래서 정확도 향상은 대부분 교사가 라벨 없는 문장에 라벨을 붙여 준 효과입니다.
- **soft label이 실제로 개선한 것:** 같은 데이터로 학습해도 S3가 S4보다 확률 품질이 좋습니다. 정답 NLL은 0.55에서 0.40으로, ECE는 0.09에서 0.06으로 낮아졌습니다.
- **과적합 완화:** S1은 200개를 20 epoch 반복해 학습 CE가 약 2e-5까지 떨어졌습니다. 같은 200개에 KD를 더한 S2는 정확도가 +2.5%p에 그쳤지만 NLL은 절반으로 줄었습니다.
- **교사의 우위는 라벨에서 나왔습니다:** 같은 라벨 2,000개로 학습하면 학생(S5 88.2%)과 교사(88.1%)의 정확도가 같습니다. MoE 구조 때문이 아닙니다.

**한계**
- 데이터셋 하나, 교사 seed 하나, 학생 seed 셋입니다.
- 하이퍼파라미터는 실행 전에 고정했고 탐색하지 않았습니다.
- 평가는 6개 후보 중에서 고르는 방식입니다. 자유 생성은 300문항만 확인했고, 학습한 모델은 모두 유효한 라벨로 답했습니다.
- 체크포인트는 저장하지 않았습니다. 다시 확인하려면 같은 명령을 다시 실행해야 합니다.
