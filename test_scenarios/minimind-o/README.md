# MiniMind-O 수동·통합 검증

## VLM 기반 T2A·A2A 학습

- 기반 모델: `caspar/MiniMind-V-Dense-64M-LLaVA-Short-v1.0`.
- 데이터: `jingyaogong/minimind-o_dataset`의 `sft_t2a_mini`, `sft_a2a_mini`.
- 각 저장소 리비전은 실행의 `artifacts/revisions.json`에 고정한다.
- 실행 코드는 `projects/minimind-o/scripts/runpod_vlm_audio/README.md`를 따른다.
  GPU 대여·학습·업로드는 명시적으로 요청받은 경우에만 실행한다.

### 절차와 판정

1. 원본 VLM과 저장한 토크나이저의 전체 어휘·ID·backend가 일치하는지 확인한다.
2. seed 42로 데이터셋별 검증 128행, 테스트 128행을 분리한다.
   세 분할이 겹치지 않아야 하며 두 평가 분할 모두 학습에서 제외한다.
3. 학습 전후 동일한 테스트 행에서 텍스트 손실과 음성 손실을 측정한다.
   음성 손실에는 종료 토큰 10배 가중치가 적용되므로 일반 CE와 혼동하지 않는다.
4. 학습 단계별 전체 행 처리 수, 누락 수, 수치 오류와 체크포인트를 확인한다.
   저장한 최종 체크포인트를 strict 모드로 다시 로드한다.
5. VLM 언어 백본·LM head·시각 projector의 모든 텐서를 원본과 비교한다.
6. T2A·A2A 테스트 분할에서 각각 앞의 3개 행으로 첫 질문을 입력한다.
   A2A에서는 음성 특징만 입력하고 질문 전사와 참고 정답을 프롬프트에 넣지 않는다.
   seed 42, temperature 0.3, top_p 0.9, max_new_tokens 512를 사용한다.
7. 생성 텍스트와 24 kHz WAV, A2A 입력 WAV, 참고 정답, 생성 길이 및 자동 전사를 보관한다.
   음성의 유한 값·비무음 여부·최대 길이 도달과 실제 질문에 대한 답변 정확성을 확인한다.
   파형 생성이나 손실 감소만으로 의미 정확성·청취 품질을 통과 처리하지 않는다.
8. 배포용 추론 스크립트로 모델을 새로 로드해 실행하고, 업로드 후 모든 파일의
   Git/LFS 해시를 로컬 파일과 비교한다. 이 실행에서 생성한 Pod와 볼륨의 삭제를
   별도의 API 읽기로 확인한다.

검증 결과·로그·환경·샘플은 루트 `outputs/minimind-o/<실행 ID>/`,
판정과 미실행 항목은 `reports/minimind-o/<실행 ID>.md`에 저장한다.
본 문서는 재사용할 절차이며 실행 성공의 증거가 아니다.
